# PBI-01 — 面のかたちを選べるようにする（切替基盤と設定）

状態: **完了**（2026-08-01） ／ 依存: なし ／ 見積り: **1.5〜2人日**

→ 実際にどう作ったか・PBIから逸れた判断・積み残しは末尾「## 完了記録」を参照。

---

## なぜやるか

`docs/web-uiux-experiment/` で、定石を壊した3案を実データのモックまで作って審査した。
結論は「骨格は案B、読む面の組版は案C、想起の一手は案A」だったが、**紙の上の審査には限界がある**——
案Aの最大の賭け（方向の記憶が1日数分の利用頻度で育つか）も、案Bの最大の賭け（上向きの組版に体が馴染むか）も、
**数日使ってみないと答えが出ない種類の問い**だからだ。

そこで A と B を実装し、現行の「日報」と**切り替えて実地で比べる**。
このPBIはその土台——**どの面を使うかを選べる仕組み**を作る。

これを A・B のどちらかに含めると、**片方が終わるまでもう片方が動かせない**（依存が直列化する）。
だから独立させる。

## ユーザーストーリー

> 読者（オーナー本人）として、**読む面のかたちを自分で選びたい**。
> 気分や場面で切り替えて、どれが自分に一番合うかを実際に使いながら見極めたいからだ。
> そして**切り替えても、読んだ記録や溜めた伝票は失われないでほしい**。

## スコープ

### やること
- 面を3つから選ぶ仕組み（`日報` / `親指ひとつ` / `一本の欄`）と、その永続化
- 設定画面。**どの面からでも到達できる**こと
- 既存の `web/src` を「共有の芯」と「面ごとの層」に分ける（下記§設計メモ）
- 現行UIを `日報` という1つの面として、**振る舞いを変えずに**新構造へ移す
- ディープリンクの契約（面が変わっても `#/note/:slug` が生き続ける）
- `web/DESIGN.md` の更新（**これは必須**。§受け入れ条件を参照）

### やらないこと
- 面A・面Bの中身（→ PBI-02 / PBI-03）。このPBIでは**空の面が2つ登録されているだけ**でよい
- 面ごとの設定項目（利き手など）。それは各面のPBIで持つ
- 面の自動切り替え（時間帯や端末で勝手に変える等）。**選ぶのは人**
- 3つの面のデザインを統一すること。**揃えないのが目的**

## 受け入れ条件

判定可能な形で書く。実装者はこれを1つずつ潰す。

### 切り替えと永続化
1. 設定画面で3つの面から1つを選べる。選ぶと**即座に**その面に切り替わる（リロード不要）
2. 選択は `localStorage`（キー `mn.face`）に保存され、次回起動時も維持される
3. **未設定のときの既定は `日報`**（現行の振る舞い）。つまり何もしなければ今までと同じ
4. 保存された値が未知の文字列だった場合、`日報` に落ちて壊れない

### 到達性（ここが一番事故りやすい）
5. **3つの面すべてから設定画面に到達できる**。各面の作法に沿った導線でよいが、
   「その面のUIを覚えていないと設定に戻れない」状態を作らない
6. `#/settings` を直接開けば、**どの面が選ばれていても**設定画面が出る（面に依存しない脱出ハッチ）
7. 設定画面には各面の**1行説明**があり、選ぶ前に何が起きるか分かる

### 状態の共有（切り替えで失われないこと）
8. 次の `localStorage` の状態は**全面で共有**され、面を切り替えても引き継がれる:
   `mn.recall.shadow`（影SRS）／`mn.recall.pending`（未送信の判定）／`mn.recall.log`（再読の履歴）／
   `mn.slips`（伝票）／`mn.seen`（最近見たもの）／`mn.atlas.<slug>.read`（章の読了）
   → **面ごとに別キーを切らないこと。** 切ると、面を変えた瞬間に積み上げが消える
9. 同じ日に面を切り替えても、**今日出る想起カードの顔ぶれと順序が変わらない**
   （日替わりは日付シードのハッシュで決まる＝`lib/edition.js` の `dayIndex`/`hash32` を全面で共有する）

### ディープリンク
10. `#/note/:slug`・`#/follow/:name`・`#/atlas/:slug/concept/:cslug`・`#/log/:topic/entry/:slug` は、
    **どの面が選ばれていても**その対象を開ける（面ごとの流儀で表示してよいが、404にしない）
11. 旧ルート（`/notes`・`/logs`・`/moc/:slug`）のリダイレクトは現行どおり生きている

### 構造
12. `web/src/lib/**` は**面から独立**している。面のコードが `lib/` に面固有の分岐を持ち込んでいない
13. `日報` の面は、この作業の前後で**見た目・操作が変わっていない**（移設のみ）
14. 選ばれていない面のCSSが、選ばれている面に**漏れていない**（面ごとにスタイルを閉じる）

### 実験としての終わらせ方 ★これを落とさない
15. `web/DESIGN.md` に**この3面構成が実験であることと、1本に絞る判断のやり方**が書かれている。最低限:
    - 観測期間（例: 4週間）
    - 判断に使う材料（`mn.recall.log` から取れる「面ごとに何日使ったか・何枚再読したか」）
    - **絞ったあと、負けた面のコードを消す**という約束
16. 設定画面に、**その面を何日使ったか**が出る（面ごとの利用日数を `localStorage` に記録する）。
    絞る判断をするときの唯一の客観データになるため
    → ただし「未消化の借金」型の数字は出さない（`DESIGN.md` 原則3）。**使った日数は増えるカウンタなので可**

### 文書
17. `web/DESIGN.md` が**同じコミットで**更新されている（`CLAUDE.md` の運用規約）。更新すべき箇所:
    - §4 情報構造（IA）— 「4タブの1枚」という前提が「面を選べる」に変わる。**これは思想の変更**
    - §8 意図的にやらないこと — 「面の自動切り替えはしない（選ぶのは人）」を足す
    - §9 既知の未達 — 3面並行の保守コストと、絞る期限
    - **新しい原則を足すなら、なぜ必要になったか（どの失敗から学んだか）を必ず書く**

## 設計メモ

### ディレクトリの切り方

現行の `web/src` は「共有の部品」と「画面」が同じ階層に並んでいる。面が3つになると破綻するので分ける。

```
web/src/
  lib/            ← 共有の芯。触らない（データ復号・索引・被リンク・紙面編成・影SRS・伝票）
    data.js  crypto.js  wiki.js  graph.js  edition.js  recall.js  ctx.js
  shell/          ← 新規。面の選択・設定・ディープリンクの受け口
    face.js         面の登録簿と現在の面（localStorage `mn.face`）
    Settings.jsx    設定画面（面の選択・各面の説明・使った日数）
  faces/
    daily/        ← 現行「日報」。既存の jsx をそのまま移す
    thumb/        ← 面A（PBI-02）。このPBIでは stub でよい
    field/        ← 面B（PBI-03）。同上
```

**判断の基準**: `lib/` に入れてよいのは「どの面でも同じ答えを返すもの」だけ。
面によって答えが変わるもの（何をどう並べるか・どう操作するか）は `faces/` に置く。

### 面の登録簿

面は「1つのコンポーネント＋メタ情報」として登録する。増減が1箇所で済む形にすること。

```js
// shell/face.js のイメージ
export const FACES = [
  { id: 'daily', label: '日報',       hint: '今日の紙面を上から読む。いまのかたち',        Root: DailyRoot },
  { id: 'thumb', label: '親指ひとつ', hint: '左下の一点だけで操作する。上は読むだけ',      Root: ThumbRoot },
  { id: 'field', label: '一本の欄',   hint: '下の欄に打つと面が変わる。タブは無い',        Root: FieldRoot },
];
```

`label` は**読者に見せる語**。`日報`・`親指ひとつ`・`一本の欄` は比喩の名前であって内部語彙ではないので、
`DESIGN.md` の「画面に内部語彙を出さない」に抵触しない。**`モードA` `案B` のような呼び方は画面に出さないこと。**

### ルーティングをどう扱うか

ここが一番の設計上の分岐。

- 現行（日報）は `HashRouter` ＋ 7ルート。
- 面Aは独自ナビゲーション（原点からの方向）。
- 面Bは**ページ遷移そのものを廃止**する（欄の中身で面が決まる）。

したがって**共通のルータを全面に強制できない**。次の契約にする:

- **`shell` が握るのは2つだけ**: `#/settings` と、**対象を開くディープリンク**（`#/note/:slug` など）
- ディープリンクで入ってきたら、`shell` が「この対象を開いた状態で始めてくれ」と面に渡す
  （面は `initialTarget` を受け取り、自分の流儀で表示する）
- それ以外の画面内の移動は**各面の自由**。URLに出す／出さないも面が決める
- ただし**iOS の PWA standalone にはブラウザの戻るが無い**ので、
  どの面も「1つ前に戻る」手段を自前で持つこと（現行の `01-thumb-zone.md` §5 の指摘）

### 既存コードの移し方（日報）

`App.jsx` から次を切り出す:
- 残す（`shell` へ）: `PasswordGate`・データ読み込み・`DataCtx.Provider`・`ScrollManager`
- 移す（`faces/daily/` へ）: `HashRouter` と `Routes`・`BottomTabs`・各ページ

`ui.jsx` は**面をまたいで使えるもの**（`Md`・`Sparkline`・`Delta`・`relDay`・`copyText`）と
**日報の見た目に属するもの**（`AppBar`・`BottomTabs`・`Card`・`Slot`・`Chip`）が混ざっている。
前者は `lib/` か `shared-ui/` へ、後者は `faces/daily/` へ。
**面A・面Bはグラスもボトムタブも使わないので、後者を引きずらせないこと。**

### Chakra UI の扱い

現行は Chakra v3 を使っているが、**面A・面Bは両方とも「Chakra を外して素のCSSにする」**と提案している
（`a-rationale.md`・`b-rationale.md` の実装コスト節）。3面が同居する間は Chakra が残るので:

- 面A・面Bは Chakra を**import しない**（バンドルに入るのは日報の分だけ）
- 面ごとのCSSは、その面のルート要素にスコープを閉じる（`data-face="thumb"` 等）。
  受け入れ条件14はこれで満たす
- 将来 `日報` を落としたら Chakra ごと消せる状態にしておく

### 実際にどう作ったか

```
web/src/
  lib/            触っていない（面から独立。面の名前を一切知らない）
                  ＋ recall.js に setLogSource() だけ追加 —— 「どの面で判定したか」の
                    ラベルを記録に添えるためで、lib はそのラベルを解釈しない
  shared/         面をまたいで意味が同じ部品。UIライブラリに依存させない
                  theme.js / util.js（relDay・copyText）/ Md.jsx / Sparkline.jsx（Sparkline・Delta）
  shell/          face.js（登録簿・利用日数）/ hash.js（URLの契約）/ ctx.js /
                  Settings.jsx / Gate.jsx（復号ゲート）/ shell.css
  faces/daily/    現行UI一式。ルータ・ボトムタブ・グラス・ChakraProvider をここに閉じた
  faces/thumb/    stub（PBI-02）
  faces/field/    stub（PBI-03）
  App.jsx         shell の本体（復号 → 面の決定 → 設定 or 面 を出す）
```

**面の登録は `shell/face.js` の `FACES` 配列1箇所だけ。** 面を1つ足す／消すのに触るのは
この配列と `faces/<id>/` ディレクトリのみ。面は `React.lazy` で動的 import しているので、
日報の Chakra は他の面のチャンクに混ざらない（実測: daily 378kB / thumb・field 各 1.3kB）。

**面コンポーネントの契約**は次の3つだけ:

```jsx
export default function XxxRoot({ initialTarget }) { ... }   // initialTarget は null か {route, kind, slug}
const { face, openSettings, initialTarget } = useShell();     // shell に頼めること
const { site, idx, graph, shadow, reads, refresh } = useData();
```

登録簿には `ownsUrl` を持たせた。日報のように自分で URL を書き換える面では shell は hash を
追いかけず（追うと面が動くたびに shell まで再描画される）、URL を持たない面ではディープリンクを
`initialTarget` として渡し続ける。

### PBI から逸れた判断

1. **`ScrollManager` は shell ではなく `faces/daily/` に置いた。**
   設計メモでは shell に残す想定だったが、`useLocation`/`useNavigationType` に依存するため
   ルータの外では動かない。ルータを持たない面がある構成では shell に置けない。
2. **復号ゲートを Chakra から素の CSS に書き直した。**
   `ChakraProvider` を日報の中に入れる（＝日報を落とせば Chakra ごと消える状態にする）ための代償。
   暗号化ビルド（`MN_SITE_PASSWORD=... node scripts/build-data.mjs`）で
   誤パスワード・正パスワードの両方を実機確認済み。見た目は元とほぼ同じだが、完全一致ではない。
3. **面を変えたら入口（`/`）から始める。** 直前まで見ていたページは前の面の流儀の産物で、
   次の面に同じ場所があるとは限らないため。ディープリンクで入ってきた場合だけは対象を引き継ぐ。
4. **`lib/recall.js` に `setLogSource()` を足した。** 条件12（lib を面から独立させる）に触れるが、
   lib が受け取るのは**解釈しないラベル**だけで、分岐は1つも増えていない。
   これが無いと条件15の「面ごとに何枚再読したか」が取れない。
5. **観測期間の起点は「土台ができた日」ではなく「3面に中身が入った日」**とした（DESIGN.md §9）。
   中身の無い面を数えても比較にならない。

### 積み残し

- **`親指ひとつ` と `一本の欄` は中身が無い。** いまはどちらも「まだ作られていない」旨と、
  ディープリンクで来た対象の素朴な表示、設定への脱出口だけ。→ PBI-02 / PBI-03。
- **「面」という語が画面上で2つの意味を持っている**（日報のタブ名＝今日の紙面／設定＝読むかたち）。
  応急処置として設定側に「いまは『日報』」と添えてある。1本に絞るときに改名して解消する
  （DESIGN.md §9 に記載）。
- **PWA の Service Worker と面の切り替えの相性は未検証。** 実機（iOS ホーム追加）で
  面を切り替えたときのキャッシュ挙動は見ていない。
- **面ごとの設定項目（利き手など）の置き場所は決めていない。** 各面のPBIで持つ想定のまま。

### PBI-02 / PBI-03 の実装者への申し送り

- **面の登録は `shell/face.js` の1行**。`Root` は `React.lazy(() => import('../faces/<id>/index.jsx'))`。
  `ownsUrl` は「自分で URL を書き換えるか」。書き換えないなら `false` のままにする。
- **CSSは必ず `[data-face="<id>"]` 配下に閉じる**。ルート要素に `data-face` を付けること。
- **`@chakra-ui/react` を import しない**。共有部品は `shared/`（Chakra 非依存）にある。
  日報の `ui.jsx`（AppBar・BottomTabs・Card・Chip・Slot・Backlinks・CopyButton）は**日報の持ち物**なので使わない。
- **共有していいもの**: `lib/**` 全部（影SRS・伝票・紙面編成・グラフ・検索素材）、`shared/**`。
  **共有してはいけないもの**: `faces/daily/**`。
- **`localStorage` のキーを新設しない**。面の状態が要るなら `mn.face.*` 名前空間に置き、
  想起・伝票・読了の6キーには面ごとの枝を生やさないこと（DESIGN.md 原則12）。
- **設定への導線を必ず1つ持つ**（`useShell().openSettings()`）。これが無い面は出荷しない。
- **「1つ前に戻る」を自前で持つ**。iOS の PWA standalone にはブラウザの戻るが無い。
