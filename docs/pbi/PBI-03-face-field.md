# PBI-03 — 面「一本の欄」を実装する

状態: **未着手** ／ 依存: **PBI-01** ／ 見積り: **3〜5人日**

---

## なぜやるか

現行の面は4つのタブで「いまどの目的か」を先に宣言させている。だが muninn の4つのジョブは**同格の目的地ではない**。
タブは「同格の行き先が4つある」ことの表明にすぎず、そこに嘘がある。

この面は**「画面」という単位ごと捨てる**。あるのは一枚の面と、下に常駐する一本の欄だけ。
**面の中身は、欄の中身だけで決まる。**

原型は Notational Velocity（2005）——検索欄がそのまま作成欄で、
ユーザーは「これから検索するのか、作るのか」という**メタな決定を先にしなくていい**。
その先祖は Jef Raskin の Canon Cat（1987）の LEAP キーで、
Raskin が最も戒めた「モード」を消すための設計そのものだ。

そして muninn は、その条件を偶然すべて満たしている——**読み手はひとり、全データが200ノードでメモリ上にあり、書き込みが存在しない。**

決め手は最後の一手。NV の「見つからなければ、そのまま作る」を、読み専用という制約下で
**「見つからなければ、そのまま Claude への依頼になる」**へ翻訳できる。
**muninn に無かったという事実そのものが、次の蓄積の入口になる。**

## ユーザーストーリー

> 読者として、**何かを思い出したいとき、いきなり打ち始めたい**。
> どのタブに行けばいいかを先に決めるのが面倒だからだ。
> そして**打って見つからなかったときに、そこで終わりたくない**——
> 「無かった」ことが、そのまま Claude への依頼になってほしい。

## スコープ

### やること
- 面「一本の欄」の全体（4ジョブすべてが成立すること）
- 常駐する入力欄と、その中身で決まる面の状態遷移
- 全concern横断のインクリメンタル絞り込み
- ゼロヒットから依頼への変換
- 想起カードを「打たない状態」の既定コンテンツとして出す

### やらないこと
- 面の切り替え機構と設定画面（→ PBI-01）
- データ層・被リンク計算・影SRS・伝票（`lib/` の共有分をそのまま使う。**作り直さない**）
- 面Aとの見た目の統一（**揃えないのが目的**）
- 専用の検索インデックス（200ノードなら総当たりで数ms。**過剰設計しない**）

## 受け入れ条件

### 構造（この面の主張そのもの）
1. **タブが無い。** 4つのジョブが「別のページ」として存在しない
2. 入力欄が画面下部に**常駐**している
3. **欄を空にすると必ず元の面（今日差し出されるもの）に戻る**
   — 押している間だけのモード（quasimode）であり、トグル型のモードを作らない
4. 面の並びに**法則がひとつだけ**あり、それが全状態で貫かれている
   （例:「欄に近いものほど強い」＝結果も今日の紙面も欄の真上から上へ積む）

### 打たない状態 ★この面の生死を分ける
5. **欄が空のときの面が、この面で一番豊かである**。スクロールするだけで一日ぶんの読み物が成立する
6. 空の状態に少なくとも次が含まれる: 想起カード／今日の一本／定点の推移／連載のつづき／在庫への入口
7. **起動直後に自動でキーボードが出る前提の設計にしない**（iOSでは JS からの `focus()` が効かないことが多い）。
   キーボードが出なくても空欄の面だけで完結する
8. 前回の入力が残った状態で起動しない（**主役である空欄の面が初見で見られなくなる**）

### 打っている状態
9. 打つそばから全concern横断で絞り込まれる（記事・定点・人・章・記録・束）
10. **ソフトキーボードに隠れる場所に何も置かない**。結果は隠れない位置に出る
11. 入力欄の `font-size` は16px以上（iOSの自動ズーム防止）
12. IMEの変換確定Enterを送信/実行として誤処理しない（`isComposing` と `keyCode 229` の両方を見る）
13. `visualViewport` の `resize`/`scroll` を購読し、キーボード表示時も欄が追従する
    （`window.innerHeight` は変化しない。**ここがこの面の生命線**）

### モードの可視化 ★人間工学からの指摘
14. **いまどの状態か（空／絞り込み中／束ねている／依頼／ゼロヒット）が、
    色・記号・文言のうち2チャネル以上で常時見えている**
    → テキストの有無だけで状態が変わる暗黙のモードは、Raskin が言うモードエラーの典型になる
15. 使える記号や書き方の**ヒントが常時画面に出ている**（隠しコマンドにしない。使いながら覚えられる形）

### ゼロヒット ★この面の核
16. 結果がゼロのとき「ありません」で終わらせず、**Claude への依頼に変換される**
17. ゼロヒットの面に、少なくとも「近いもの（あいまい一致）」と「ここから先は muninn の外＝依頼の選択肢」が出る
18. 依頼はクリップボードへ写せ、伝票にも溜められる

### 想起
19. 想起カードが**モード切替なしで**空欄の面に流れてくる（クイズ画面に入るという操作が無い）
20. 問い → めくる → 判定 まで到達でき、判定は画面に反映される
21. **判定の取り消しがある**。トーストが消えたあとも取り消せる手段が残っている
22. **59という総量を画面に出さない**。出してよいのは「今週N件 再読した」型の**増える**カウンタだけ

### 4つのジョブと行き止まり
23. 見渡す（在庫の俯瞰）ができ、**ゴルフが約半分という偏りが見て分かる**
24. すべての詳細画面に「**ここへ来る道**」（被リンク）があり、**リンク元が書いた理由ごと**読める。行き止まりがゼロ
25. 本文中のリンクを、**遷移せずに理由ごと覗ける**

### 越えてはいけない線（`RESEARCH-DIGEST.md` §B）
26. タップ標的は44×44px以上
27. `backdrop-filter` を縦スクロールするカード全部に付けない
28. `prefers-reduced-motion: reduce` で動きが無くなる
29. アニメーションは `transform` と `opacity` のみ。反応は100ms以内
30. `lib/` の localStorage キーを共有している（PBI-01 の受け入れ条件8）

### 戻る
31. **iOS の PWA standalone にはブラウザの戻るが無い**ので、深いところへ入ったときに戻る手段を自前で持つ
    （欄を消せば戻る、という法則で足りるならそれでよい。ただし詳細を開いた状態からの復帰は要確認）

## 設計メモ

### 状態機械

欄の中身から面の状態を決める。**分岐は少なく、法則はひとつ。**

```
空            → 今日差し出されるもの（想起・今日の一本・定点・連載・在庫）
文字          → 全concern横断の絞り込み
記号で始まる  → 別の意味（例: # で在庫を束ねる、> で依頼）
文字＋ゼロヒット → 「ここから先は muninn の外」＝依頼への変換
```

記号の割り当ては実装者が決めてよいが、**ヒントを常時出す**こと（受け入れ条件15）。
コマンド駆動UIの最大の弱点は発見可能性で、隠した瞬間に使われなくなる。

### 検索の実装

**専用インデックスを作らない。** 全データは復号済みでメモリ上にあり、200ノード規模なら
素の総当たりで数ms〜十数ms。`lib/graph.js` の `nodes` をそのまま舐めればよい。
debounce も体感上は不要（入れるなら連続入力時の再描画コストへの保険として）。

### 「上へ積む」という賭け

この面は「欄に近いほど強い」＝**重要度の軸を下向き**にする。
結果として「一番強いもの＝親指のいちばん近く＝ソフトキーボードの直上」が構造的に保証される。

ただし**スクロール位置が下端に固定されるのはチャットやターミナルの文法であって、読み物の文法ではない。**
実地で使って「毎回いちばん上を見失う」と感じるなら、それがこの面の答え（＝負け）だと判断してよい。
オンボーディング1枚で足りるかどうかは、この面が抱える唯一にして最大の賭けである。

### 想起の判定をどう取るか（要判断）

現行実装は「2択＋**一言を書いたか**」で q を 5/4/2 に分岐させている。
**一言を書く行為そのものが定着に効く**（能動的な再構成）ので、これは意味のある仕組みだ。

一方この面は「一本の欄」を主張するので、カードの中に第二の入力欄を置くと骨格が崩れる。
モックでは**自由記述を捨てて「粘った時間」から推定**する形にした（`b-rationale.md` の弱点7）。

**実装時に決めること**: 一言を残すか、粘った時間で代替するか。
残すなら「欄は一本」の主張をどう保つか（例: 判定のときだけ**下の欄そのものが一言の入力欄になる**——
これなら欄は増えない）。**この案を推す**が、実装者の判断でよい。決めたら `DESIGN.md` §6 に反映すること。
