# PBI-04 — `writings/`（創作）をサイトで読めるようにする

状態: **未着手**（起票 2026-09-05）／ 依存: **PBI-01**（面の切替基盤）／ 見積り: **1.5〜2.5人日**

---

## なぜやるか

2026-09-05 に6つ目の concern として `writings/`（お題 → 執筆 → 講評 → 改稿 → 作品）を追加した。
正本の markdown と `/mn-write` skill は動いているが、**サイトが `writings/` を一切読まない**。

muninn の前提は「**書くのは Claude Code、読むのはサイト**」（CLAUDE.md）。
このまま放置すると、作品と講評だけがサイトから見えない例外になり、その前提が崩れる。

特にこの concern は**推移が見える価値が大きい**。5軸のスコアが版ごとに `rounds` に入っているので、
`follows` の Sparkline とほぼ同じ材料が最初から揃っている。読めないのはもったいない。

## ユーザーストーリー

- 読者（＝運営者本人）が、外出先のスマホから**書きかけの作品と直前の講評**を開き、次の稿の重点だけ確認したい。
- 完成した作品を**作品として読む**（講評抜きの完成稿だけを、まとまった読み物として）。
- 「自分の引きの点は伸びているのか」を、作品をまたいだ**軸ごとの推移**で見たい。

## スコープ

**やること**

- `web/scripts/build-data.mjs` が `writings/` を読み、`site.json` に `pieces` を出す（`rubric` の軸定義も）。
- 作品の詳細ルート（`#/piece/:slug`）。版・講評・重点を読める形で組む。
- 完成稿がある作品は、**完成稿を先に、版の履歴を折りたたみで後ろに**置く（読み物として読める順序）。
- 3つの面すべてに導線を1本ずつ（面ごとの流儀に従う。新しい面の発明はしない）。
- スコア推移の可視化（既存 `Sparkline.jsx` の再利用。**新規のグラフ実装はしない**）。

**やらないこと**

- `prompts.md`（お題ストック）はサイトに出さない。**運営の楽屋であって読み物ではない**（`collect.md` と同じ扱い）。
- サイトからの投稿・改稿 UI。`web/DESIGN.md` 原則「サイトに書き込み UI は作らない」に従う。
  ただし**「この重点で改稿する」を伝票（Claude への依頼）に積む**のは既存の枠内なので可。
- 作品の全文検索の作り込み（既存の検索に載るところまで）。

## 受け入れ条件

1. `npm --prefix web run build:data` が `pieces N` を出力し、`writings/pieces/*.md` の件数と一致する。
2. `rubric.md` の `axes` に無い key が piece の `scores` に含まれていたら**ビルドが落ちる**（`logs` のスキーマ検証と同じ思想＝一貫性の砦）。
   `total` と各 `scores` の合計が食い違う場合も落とす。
3. `status: done` の作品を開くと、**最初に見えるのは完成稿**である（講評が先に来ない）。
4. `status: drafting` の作品を開くと、**最新版とその重点が1画面目に入る**。
5. 3つの面すべてから、`#/piece/:slug` に**行き止まりなく**到達できる（`DESIGN.md` 原則6）。
6. 軸ごとのスコア推移が、少なくとも1箇所で時系列に見える。

## 設計メモ

- **データ**: piece の frontmatter の `rounds[]` がそのまま系列データ。`follows` の `metric_goals` に相当するものは
  「全軸 up が正」で固定でよい（点は高いほど良い、が自明な唯一の指標なので宣言を持たせない）。
- **本文の切り出し**: 版と講評は本文中の `## v1` / `### 講評` 見出しで区切られている。
  frontmatter に本文を重複させない（`atlas` の concept と同じ方針）。パーサは見出しベースで素直に切る。
- **語彙**（`DESIGN.md` 原則14・17: 内部語彙を画面に出さない）: piece → **作品**、round/version → **稿**、
  rubric → **評価の軸**、prompt → **お題**、focus → **次に直すところ**。「ルーブリック」「ピース」は画面に出さない。
- **`DESIGN.md` の更新が必要**: この concern は muninn で**唯一のアウトプット**であり、
  「想起の二層モデル」にも「日報の組版モデル」にも素直には乗らない。
  実装と同じコミットで、**書いたものをどう面に載せるかの思想**を `DESIGN.md` に書くこと（CLAUDE.md の⛔ルール）。
  少なくとも「未完成の作品を新着として出すべきか（＝書きかけを毎朝突きつけるのは励ましか呪いか）」には
  結論を出す必要がある。**未完了タスクを負債として数えないという原則3と正面から関係する。**
