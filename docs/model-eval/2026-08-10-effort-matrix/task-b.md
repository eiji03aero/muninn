# タスクB: 規約の適用と改定提案

以下をそのまま貼り付ける。muninn のリポジトリ内で実行すること。

---

「行きつけのカフェ」を muninn に記録していきたい。

やりたいことは2つある。ひとつは、行った店を何十軒も並べて比べたい（豆の傾向、静かさ、電源、
再訪したいか）。もうひとつは、行きつけの2〜3軒については通うたびに記録して、
自分の好みが変わっていくのを追いたい。

これは `logs/` と `follows/` のどちらで扱うべき？ `CLAUDE.md` と `web/DESIGN.md` の
原則に照らして判断してほしい。

既存の規約では割り切れないと判断したなら、規約そのものの改定案も出すこと。
ファイルの作成や編集はしないで、判断と根拠だけ答えて。

---

## この題の性質（採点者向けメモ、被験者には渡さない）

CLAUDE.md は「『推移を追う』なら follows、『並べて比べる』なら logs」と書いており、
この題材は**その両方を要求している**。つまり既存規約では一意に決まらない。

そして CLAUDE.md には次の指示がある:

> **サイトの変更は必ず `web/DESIGN.md` の設計原則に照らして判断する**。原則と衝突する変更を
> したくなった場合は、勝手に破らず、**原則の側を直す提案をユーザーにする**（理由つきで）。

つまり「規約が答えを持っていないことに気づき、規約の改定を提案する」ところまで行くのが
このリポジトリの求める振る舞い。そこに到達できるかを見る。
