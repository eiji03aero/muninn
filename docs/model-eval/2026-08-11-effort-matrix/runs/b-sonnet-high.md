いいか、よく聞け！これは典型的な「二階建て」の話だ。1つの結論じゃ割り切れない、でも規約に矛盾してるわけでもない。順番に整理するぞ！

## 結論

- **「何十軒も並べて比べたい」** → `logs/`（例: `logs/cafes/`）
- **「行きつけ2〜3軒を通うたびに記録して好みの変化を追いたい」** → `follows/`（`follow_type: interest`、1店1ディレクトリ）

そして重要なのは、**この2つは排他じゃなく併用が正解**ということだ。行きつけの店も、最初は「何十軒」の1つとして logs に入っていたはずだろ？それが「もっと知りたい」対象に育っただけだ。竹と同じだよ、根っこ（logs の1件）はそのままに、新しい枝（follows）が伸びていくイメージだ！

## 根拠

### logs 側の根拠
`CLAUDE.md` の logs 定義そのものだ。

> follows は**1つの対象**を時系列で定点観測。logs は**多数の別々の項目**を同じ項目で並べて比較する（各記録は主に1回きり）。「推移を追う」なら follows、「並べて比べる」なら logs。

「何十軒」「豆の傾向・静かさ・電源・再訪したいか」というスキーマで横並び比較したい欲求は、この定義に完全一致する。`web/DESIGN.md` §5 の紙面組版モデルにも `series → compare` という別カード型が定義されていて、`compare` は logs の比較テーブル専用の枠だ（§9「記録帖の比較テーブルが実データで検証できていない」からも、この機能はまさにこの用途のために作られている）。

### follows 側の根拠
同じく CLAUDE.md の follows 定義。

> follows は「同じ対象を何度も観る」定点観測。**profile.md には変遷タイムライン**を持つ。

行きつけ2〜3軒を通うたびに記録し、自分の好みの変遷を追う——これは golf のドライバー距離や好きなサッカーチームと構造的に同じだ。`follow_type` は **`interest`（goal ではない）** を薦める。理由は、君がやりたいのは「特定の目標値に近づける」ことじゃなく「深く理解して楽しむ」ことだからだ。豆の産地・焙煎の違いを深掘りしながら、自分の舌がどう変わったかを"見どころ"として記録していく——これは interest 型の「記録＋見どころ・深掘り」にそのまま乗る。goal 型のような「アドバイス」を出す必要はない。

`web/DESIGN.md` §5 の `series` カード型が follows のセッション推移を表示する枠として既に用意されている点も、この判断を裏付ける。

## 規約で割り切れない部分（改定案）

ここからが本題だ、燃えてきた！CLAUDE.md の「follows との違い（間違えないこと）」の節は、**対象ごとに logs か follows かを一発で決める前提**で書かれている。だが君のユースケースは「同じ店」が logs（初回の1件比較）にも follows（その後の定点観測）にも**両方またがる**ケースだ。これは今の文言だと想定されていない。

具体的に足りていないのは以下の2点:

1. **「格上げ」のルールが無い**。logs に入っていた店が「行きつけ」に育ったとき、logs の既存エントリを消すのか、残すのか、follows と併存させるのかが決まっていない。
2. **同一実体の相互リンクのルールが無い**。`notes/` 同士の `[[リンク]]` 規約はあるが、logs entry と follows profile が同じ実体（同じカフェ）を指す場合の相互参照が規定されていない。

### 提案文言（CLAUDE.md 追記案）

`## フォロー（follows）` と `## ログ（logs）` の間、または両セクション末尾に以下を追記することを提案する：

```markdown
## logs と follows の併用（対象の格上げ）

同一の実体が logs のカタログと follows の定点観測に**同時に**属してよい。
典型例: 何十軒と比較していた店の1つが「行きつけ」になり、通うたびの変化を追いたくなった場合。

- logs 側のエントリは削除・改変しない。「並べて比べる」母集団としての役割を保つ。
- follows 側は新規ディレクトリとして独立に作る（`follows/<店名>/`）。
- **相互リンクを必須とする**: follows の `profile.md` に対応する logs entry へのリンクを、
  logs の `entry` に対応する follows へのリンクを、それぞれ本文に明記する。
- 「格上げ」の基準は「同じ対象に継続して追加記録する意思があるか」。
  1回きりの記録で十分なら logs のみに留め、安易に follows 化しない
  （follows を作りすぎると「行きつけ」の定点観測という本来の価値が薄まる）。
```

これなら既存の「logs vs follows は択一」という骨格を壊さずに、実際に起きる「対象の成長」というライフサイクルだけを追加で説明できる。矛盾じゃなく、抜けていた運用パターンの補完だ。
