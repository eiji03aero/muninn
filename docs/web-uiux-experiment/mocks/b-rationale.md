# 案B — 一本の欄

## この案が賭けているもの

賭けているのは、**「画面」という単位を捨てても muninn は成立する**という一点だ。Notational Velocity（2005）は検索欄と作成欄を同じ一本にすることで「これから検索するのか作るのか」という**メタ決定**をユーザーから取り上げた。Raskin の Canon Cat（1987）はさらに手前で、アプリケーションもファイルもやめて「文書ストリームと LEAP キー」だけにした。muninn はその条件を偶然すべて満たしている——読み手はひとり、全データが 200 ノードでメモリ上にあり、書き込みは存在しない。ならばタブ4つで「いまどの目的か」を宣言させる必要はない。**面は一枚。欄は一本。面の中身は欄の中身だけで決まる。**そして NV の最後の一手「見つからなければ、そのまま作る」を、読み専用という制約下で「**見つからなければ、そのまま Claude への依頼になる**」へ翻訳した。muninn に無かったという事実そのものが、次の蓄積の入口になる。

## 4ジョブをどう解いたか

**J1 めくる（打たない状態）— ここが本命。** 検索欄ファーストの最大の弱点は「入力しない状態が貧しくなる」ことだ（`04-command-modeless.md` 案Aのボツ理由がまさにこれ）。だから**空欄の面を一番豊かな面**として作り、そこに**ひとつの組版法則**を通した——「**欄に近いものほど強い**」。今日の紙面は上から下へではなく、**欄の真上から上へ積まれる**。欄のすぐ上に想起カード（問い→めくる→わかった／あやしい）、その上に今日の一本、定点のうごき、連載のつづき、たな、いちばん上に日付と「今週N件 再読した」。上へ遡るほど弱く・古い。これは検索結果の逆順スタックとまったく同じ法則で、**面と結果が同じ組版で説明できる**。しかも「一番強いもの＝親指のいちばん近く＝ソフトキーボードの直上」が構造的に保証される。ゆうべ開いたものを「ゆうべの続き」として拾い、記録帖・束への入口も小さく置く。**空欄でもスクロールするだけで一日ぶんの読み物が成立する。**
起動時は**必ず空欄の面から始まる**（ブラウザは `autocomplete=off` でもリロード時に input の値を復元するので、boot と `pageshow` でクエリだけ明示的に空に戻す。判定履歴・伝票・ゆうべの続きは残す）。この案の主役は空欄の面であり、そこを見せられないと案そのものが伝わらない。

**J2 見渡す。** `#` を打つと在庫が束になる。タグを本数の棒で描き、**多い順に欄へ近づける**——ゴルフ45本の棒が欄の真上に来て、47%という偏りが最初に目に入る。均等グリッドでは消えてしまう事実だ。上段には定点3・連載1・記録帖1・束5を同じ行組で並べる。`#ゴルフ` と続ければ、同じ欄のままその45本へ降りる（面は増えない、欄が変わるだけ）。

**J3 当てる。** 打てば全concern横断で即時に絞り込む（200ノード・総当たりで数ms）。結果は欄の真上から上へ。行には記事／定点／人／章／記録／束の別と、当たった箇所のハイライト。↑↓で選び Enter で開く。**キーボードが出ていても隠れる場所には何も置かない**（`04` 4章・`01` 5章）。

**J4 頼む。** `>` が依頼。空なら伝票と「こういう頼み方ができる」の見本、打てば `/mn …` の依頼文が組み上がり、伝票にためる／コピーできる。記事を読んでいて「この面のことで頼む」を押すと、その記事名が文脈として依頼文に入る。**そしてゼロヒット。**結果が全部消えたとき、欄の真上に不動で居座っていた依頼行だけが残り、そこが**燃える**。上には「ぴたりとは無い／近いのはこのあたり」（ゆるい2-gram一致）と「ここから先は muninn の外」（4つの頼み方）が並ぶ。空白を「ありません」にしない（原則7）。

## 壊した定石と根拠

- **ボトムタブ4つを全廃**（`RESEARCH-DIGEST` C-2、A-7）。目的地が同格でないならタブは嘘をつく。4ジョブは並列の場所ではなく、**欄の中身の状態**である。
- **ページ遷移と ‹戻るを廃止**（C-1、A-2）。欄に文字がある間だけ「探す面」になり、**消せば必ず元の面に戻る**。これは Raskin の quasimode そのもの（`04-command-modeless.md` 2章）——トグル型のモードではないので、事故が起きない。深いところへ移ったときだけ、欄の左に ◀ が点る。
- **上から下へ読む、を捨てた**（A-2、A-13）。組版は重み付け装置であり、モバイルでの重みは「親指からの距離」である。だから重要度の軸を**下向き**にした。実装上も、選択順は DOM の実座標から算出して法則をコードに通してある。
- **ダークグラスを捨て、等幅寄りの高密度へ**（C-5・C-6、A-13、`05-editorial-experimental.md` 1-9/1-10）。`backdrop-filter` は一つも使っていない（原則12）。和文はシステムサンセリフ、ラテン・数字だけ等幅の**混植**にした（`05` 1-10 の「等幅は和文グリフが弱い」という警告への対処）。
- **インクリメンタル検索をモバイルに持ち込んだ**が、Google Instant が死んだ理由（A-8）は素直に受け入れて、**結果を上方向に積む**という一点で回避した。技術的コストは元々ゼロに近い（D「全データがメモリ上」）。

## 想起の判定 — 2択のまま、精度は行動から取る

A-11 が指摘する既存実装の要は「**判断は2択のまま、精度は行動から推定する**」——2択＋「一言を書いたか」で q を 5/4/2 に分岐させる仕組みだ。この案では**自由記述の欄を意図的に置かなかった**。理由は一つで、**「一本の欄」という主張と第二の入力欄は両立しない**からだ。カードの中にもう一つテキストボックスを置けば画面上に入力欄が2本になり、この案の骨格そのものが崩れる（欄の意味を状況で切り替えるのも、Raskin が最も戒めたモードの導入になる）。

代わりに、A-11 の**趣旨のほう**を別の行動で実装した。**「問いを見せてから めくる まで、どれだけ粘ったか」**を測る。

| 行動 | q | 意味 |
|---|---|---|
| わかった ＋ 4秒未満でめくった | **5** | すぐ出た＝やさしい。間隔をのばしてよい |
| わかった ＋ 4秒以上粘った | **4** | 思い出せたが手間取った＝まだ危うい |
| あやしい | **2** | 出なかった |

**入力を一切増やさずに3段階が取れ**、しかも「思い出そうと粘る」という、想起そのものに効く行動を測っている（自己申告より正直でもある）。隠し判定にはせず、めくった直後に `◷ 0.2秒で めくった（すぐ出た＝やさしい扱い）` と**そのまま画面に出す**（原則8「数字に嘘をつかせない」の精神を、自分の記録にも適用した）。`q` と `ms` は履歴に残る。

**取り消しは二重で用意した。** ①判定直後に「↺ 取り消す」の帯が出て、**残り時間が細い帯でみるみる減っていく**（transform だけで描画）。②帯が消えたあとも、**カードの中に「直前: わかった（粘った）　↺ 取り消す」が居座り続ける**（次の判定をするか、取り消すまで消えない）。トーストを見逃しても取り消せる——「取り消せない操作は作らない」を、タイミングに依存しない形で満たすため。

## 「理由つき被リンク」をどう使ったか

muninn 最大の未使用資産（D、A-9）を**行き止まりの解消**そのものに使った。すべての詳細面の下端、欄の真上に「**ここへ来る道 N**」のバーが常設される。開くと、相手が書いた理由ごと逆流できる——「『同じ大会でメッシが打ち立てた記録』と書いてこちらを指している」。Wikipedia の Page Previews より一段リッチな文脈を、**遷移せずに、親指の届く場所で**読める。順方向も同じで、本文中の `[[リンク]]` も「ここから出ていく道」も、押すと**遷移せず**欄の真上に「のぞく」が生えて、種別・理由・冒頭を見せ、「ここへ移る／やめる」を選べる。**ポップアップは例外なく欄の真上から生える**——法則がひとつしかないので、どこで何が起きるか常に予測できる。

## 実装コスト見積り（React + Vite の既存実装からの差分）

- **捨てられるもの**が多い: ルータ（`#/note/:slug` 等）、下タブ、AppBar、‹戻る、Chakra UI、グラス系スタイル、ページ単位のコンポーネント。**画面数が実質1に減る**ので総量はむしろ減る。
- **新規**: 欄のステート機械（空／文字／`#`／`>`／`?`／詳細）約200行、逆順スタックの組版（CSS 30行＋位置ベースの選択順20行）、被リンク索引（`linkrefs`逆引き・30行）、riser（道／のぞき・120行）、伝票（localStorage・60行）、想起の時間計測とUndo二段（40行）。
- **移植**: 既存の詳細表示（記事／定点／人／章／記録／束）はほぼそのまま関数に落とせる。
- **注意点**: URL が消えるのでブラウザ戻るが効かない → `history.pushState` で trail を同期させる作業が別途1日ぶん要る（PWA standalone では戻るが無いので必須ではないが、Safariタブでは要る）。
- ざっくり **3〜5人日**。既存の日報実装（現行）と同規模かやや小さい。

## この案の弱点・落選しうる理由

1. **「上へ積む」は覚えるまで確実に気持ち悪い。** スクロール位置が下端に固定されるのはチャットやターミナルの文法で、読み物の文法ではない。オーナーが「毎回いちばん上を見失う」と感じたら、この案の骨格ごと崩れる。オンボーディング1枚で足りるかは賭け。
2. **`#` `>` `?` という記号語彙は、コマンド駆動UIの弱点をそのまま抱えている**（`04` 3章-5）。ヒント帯を常時出して「使いながら教える」対策は入れたが、久しぶりに開いたとき指が思い出せるかは検証していない。ここは Linear のような日次利用が前提の対策で、muninn の利用頻度で足りるかは不明。
3. **読む面だけ法則が破れている。** 記事本文は上から下へ読むので、そこだけ「欄に近いほど強い」が適用できない。一枚岩の主張に穴が一つある（道バーを下端に常設して繋いだが、理屈としては継ぎ目）。
4. **依頼のバリエーションが構造的に薄い**（`04` 案Bのボツ理由）。読み専用なので動詞が4つしかなく、`>` は「検索窓の皮を被った検索窓」に見えるリスクがある。今回は依頼の**ひな形を常時見せる**ことで具体性を出したが、実運用の依頼ログを見ずに決めた4つなので外している可能性がある。
5. **視覚的な華がない。** ターミナル寄りの高密度は「他にない」を満たすが、「日報」刷新のときにオーナーが気に入っていた質感を全部捨てている。密度＝信頼というBloomberg的な逆説（A-13）を買ってくれなければ、単に地味な案に見える。
6. **1テーマ47%という偏りを、俯瞰の棒でしか表現できていない。** 面積ツリーマップのような「偏りそのものが絵になる」表現に比べると、情報としては正しいが絵としては弱い。
7. **想起の3段階を「粘った時間」から取るのは、自由記述より情報が薄い。** 一言を書く行為そのものが定着に効く（能動的な再構成）という効能は捨てている。4秒という閾値も根拠が薄く、実運用のログを見て決め直す前提。**「一本の欄」を守るために、既存実装が持っていた良さを一つ手放した**——ここは意図的なトレードオフであり、オーナーが「一言を書く時間が一番効いていた」と言うなら、この案は判定の設計を作り直す必要がある。
