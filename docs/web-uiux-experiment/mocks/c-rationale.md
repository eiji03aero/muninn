# 案C「紙面をめくる」— 設計意図

## この案が賭けているもの

均一なカードの縦リストは、**全記事を同じ重要度で提示してしまう＝「編集していない」ことの表明**である（RESEARCH-DIGEST A-13 / `05-editorial-experimental.md` 原理1）。muninn の在庫は極端に不均一だ——ひとつの棚が全体の半分近くを占め、記録帳は1件しかない。この偏りは事故ではなく事実であり、**均等グリッドに逃げた瞬間にその事実が消える**。だからこの案は、組版そのものを編集判断の装置として使う。リードは大きく、在庫は小さい活字の密集に。棚の厚みは級数（フォントサイズ）で直接描く。そして質感はダーク＋グラスを捨て、紙・インク・活版に振った。muninn が別のプロダクトに見えるところまで振り切ることで、「今風で綺麗」の引力から離脱するのが狙いである。

## 4つのジョブをどう解いたか

**面の並び**：タブバーを廃し、4つのジョブを新聞の面立て（一面／棚／索引／伝票）にした。既定の動詞は「めくる」。タブは「同格の目的地が4つある」ことの表明にすぎないが（DIGEST C-2）、紙面の順序は「今日 → 在庫 → 引き当て → 入稿」という**手順の順序**であり、同格ではない。

**J1 今日読むものを差し出される**：一面の頭に「今日の一問」。閲覧日（`new Date()`）を FNV-1a でハッシュした決定的シードで、期限切れノートから5枚を選ぶ。同じ日は何度開いても同じ配列。伏せられた `recall` を明朝22pxで組み、めくると答え（title＋本文）が出て、わかった／あやしいを打つ。モード切替はゼロ——問いは紙面の一段目にただ組まれている。

**J2 在庫を俯瞰する**：棚の面。タグを本数に比例した級数で流し込む（ゴルフ45＝42px／知の整理1＝12px）。ワードクラウドではなく**新聞の総目次欄**として1本の活字の流れに組んだ。数字の羅列より先に「どこが厚いか」が体でわかる。押すとその棚に降り、そこでも大2・中5・小の三段扱いで組み直す。

**J3 ピンポイント想起**：索引の面。全データがメモリ上にある（200ノード）ので総当たりで数ms。**入力欄を画面下端に置き、結果はその上に積む**——ソフトキーボードが画面の40〜50%を占めても結果が隠れないため（DIGEST A-8）。ゼロヒットは「無かった」で終わらせず、依頼への入口に変換する（A-7 の NV 系譜）。加えて引き当てゼロでも「かわりに」の目の子（よく引く見出し・直近の組版）を必ず出し、面を白紙にしない。

**J4 依頼を作る／溜める**：伝票の面。原稿用紙の罫を敷いた文面欄で作り、伝票に綴じ、まとめてクリップボードへ写す。記事末・棚・ゼロヒット・帳面のどこからでも定型文が前もって入った状態で開く。

## 「めくる軸」と「読む軸」の直交をどう実装したか

**軸を分けるのではなく、入力を受ける場所を物理的に分けた。**

- 画面下端の**帯だけ**が横方向の入力を取る（`touch-action: none`、`pointerdown` は帯の上でしか始まらない）。
- 紙面本体は縦スクロールだけを取る（`touch-action: pan-y`）。横のイベントを一切見ない。

同じ面で二つの軸が主導権を奪い合う（`05` の writing-mode 節が警告する iOS Safari の典型的な破綻）ことが**原理的に起きない**。加えて画面左端20pxからの横スワイプは使っていないので iOS の戻るとも衝突しない。帯は「なぞる＝めくる（速い経路）」と「名前を押す＝直行（目で見て辿れる経路）」を同居させており、隠しジェスチャだけで到達できる機能はゼロ（越えてはいけない線3）。タップ判定は `click` イベントで行うのでキーボード・支援技術からも到達できる。

そして帯は**操作卓**でもある。想起の「めくる／わかった／あやしい」、棚の「棚へもどる」、伝票の「まとめて写す」、記事の「もどる／依頼／閉じる」——面ごとの主操作はすべてこの帯に載る。結果、操作領域は画面下から **140px** に収まり（線1の250px以内）、上は完全に「読む領域」になった。Samsung One UI の恒常的再配置（`01-thumb-zone.md` 2-3）であって、Reachability 型の一時呼び出しではない——**何も覚えなくていい**のが利点である。

**日本語組版**：Webフォントはゼロ。OS標準の明朝（Hiragino Mincho ProN / Yu Mincho）とゴシックの対比だけで組んだ（日本語Webフォントは無対策で16MB／1.7万グリフ、`05` フォント節）。縦組みは**段の柱（「今日の一問」「拾い読み」「棚おろし」「欄外」）と題字脇の「日刊」だけ**——すべて5文字以内の和文で、英数字混じりの本文には一切使っていない。`line-break` は指定していない（`05` の指摘どおり `strict` はかえって見慣れない改行を生む）。本文の `text-align: justify` は**実機で確認して外した**——`philosophia` のような欧文が混ざると行が引き伸ばされて字間が破綻したため。質感は SVG `feTurbulence` のノイズ1枚（`mix-blend-mode`）と、題字・大見出しだけの1.4pxの版ズレに留めた。

## 「理由つき被リンク」を傍注としてどう使ったか

これが muninn だけが持てる紙面表現である（DIGEST A-9 / D）。

1. **傍注（欄外の柱）**：記事本文の脇に、`linkrefs` の理由を**リンク元が書いた言葉のまま**組む。「前提: 一度目の戦争でイランが弱体化していた」→ 相手の記事名。本文に受け皿があればその段落直後、なければ「欄外」と縦組みで打った柱にまとめる。狭い画面では Tufte のサイドノートは折りたたみに退化する（`05` 1-8）が、**縦組みの柱を立てて欄という様式を与える**ことで、退化ではなく紙面の構造として読ませた。
2. **「ここへ来る道」（被リンク）**：全詳細画面の末尾に例外なく置く。相手の理由を **`「…」`の引用組み**（明朝・縦罫）にし、その下に出典を小さく置く。「なぜ向こうが自分にリンクしたか」がそのまま読める。
3. 正本の `## Links` 節は**本文に流さない**。同じ情報を二度組むのは紙面の失敗なので、傍注として組み直すのがこの面の役目である。
4. 被リンクが無い記事は「ありません」と書かず、「この記事へ通じる道は、まだ引かれていない」＋繋ぎ先を探す依頼へ変換した（原則7）。

自動検査で **126ページすべてに出口（発リンクまたは「ここへ来る道」）がある**ことを確認済み。行き止まりゼロ。

## 「越えてはいけない線」15項目の自己採点

| # | 項目 | 判定 | 補足 |
|---|---|---|---|
| 1 | 主要操作は下端250px以内 | **守った** | 操作卓は下140px。上部に主要操作は一切ない |
| 2 | タップ標的 44×44 以上 | **守った** | 帯・操作卓を実測して0件違反（◀▶を40→46pxに修正済み） |
| 3 | 隠しジェスチャ単独の機能を作らない | **守った** | めくりは「帯をなぞる」と「名前を押す」の二経路。◀▶ボタンも併設 |
| 4 | ジェスチャ語彙4種以内 | **守った** | **1種**（帯を横になぞる）のみ。長押し・ピンチ・二本指なし |
| 5 | 左端20px・下端数pxを使わない | **守った** | 横入力は帯（下端から22〜70px）に限定。画面本体は横イベントを見ない |
| 6 | 判定を取り消し不能な1操作で確定させない | **守った** | 判定直後に「直前の判定を取り消す」を帯の上に出す。時間で消えず、次の判定／面をめくる／記事を開くまで残る |
| 7 | ピンチズームを主要操作にしない | **守った** | 不使用 |
| 8 | 一度に見せるノードは12点まで／図はリストで代替可 | **守った** | 順路は `slice(0,12)`。エッジは型付きの整列リストで、図ではない |
| 9 | `prefers-reduced-motion` で動きゼロ | **守った** | `--turn` `--flip` を0msにし、全 transition/animation を無効化。ドラッグ追従は transition を使わないので影響なし |
| 10 | 反応100ms以内／transform・opacityのみ | **危うい** | 反応（状態変化）は即時。ただし**めくり170ms・カードの反転180ms**の演出が乗る。ドラッグ中は1:1追従なので体感は即時だが、タップでのめくりは170ms待つ。緩和策＝`--turn`を1変数で持たせてあるので0〜120msへ即座に落とせる。アニメーションは `transform`/`opacity` のみ（`width/height/top/left` は一切animateしていない） |
| 11 | 触覚に依存しない | **守った** | `navigator.vibrate` 不使用。確信は版ズレ・黒地反転・帯のグリップ色で作る |
| 12 | `backdrop-filter` をスクロールするカードに付けない | **守った** | `backdrop-filter` 自体を使っていない |
| 13 | 入力欄の font-size 16px以上 | **守った** | 索引欄・依頼欄とも16px（実測確認） |
| 14 | IMEの変換確定Enterを誤処理しない | **守った** | `compositionstart/end` で絞り込みを止め、`isComposing`/keyCode 229 を見る |
| 15 | 未消化件数のバッジを出さない | **守った** | 「59」は一切出さない。出すのは「本日の組み付け 3/5」（今日の分母）と「この7日で N本を読み返した」（増えるカウンタ）だけ |

**危ういのは10だけ**。それも「機能として遅い」のではなく「演出を何ms許すか」の判断で、変数1つで調整できる。

## 実装コスト見積り（React+Vite の既存実装からの差分）

- **面のめくり機構**：新規。`translateX` トラック＋帯のポインタ制御で **150〜200行**。React なら `useRef` でトラックを直接触る（再レンダリングを挟まない）。0.5〜1日。
- **紙面の組版CSS**：段（`.dan`）＋縦組みの柱＋大中小の扱い。**300〜400行のCSS**。Chakra UI を外すので実質は既存スタイルの置き換え。1〜1.5日。
- **傍注と「ここへ来る道」**：被リンク索引はクライアント側の逆引き（**20行程度**）。組版側が中心で 0.5日。既存の linkrefs をそのまま使うのでデータ変更は不要。
- **級数マップ・スパークライン**：どちらも数十行の純関数。0.5日。
- **表示語彙フィルタ（`deJargon`/`title2`/`mocTitle`）**：**50行**。正本を汚さず、表示の瞬間だけ内部語彙を読者の語に組み替える。0.5日。
- **合計 3〜4人日**程度。WebGL も重量級ライブラリも使わない。
- **フォントの運用コストはゼロ**。Webフォントを使わないので、`05` が警告するサブセット生成の常時運用（2書体×ウェイト分を毎ビルド）が発生しない。**代償は「端末によって明朝の顔が違う」こと**（iOS＝ヒラギノ明朝、Android＝端末依存で明朝が無い機種もある）。muninn の読者はiPhone1人なので実害は小さいが、この案の紙面性はヒラギノ明朝の存在にかなり依存している。
- **質感のコスト**：`feTurbulence` 1枚と `text-shadow` の版ズレだけなので保守はほぼゼロ。`mix-blend-mode` 非対応環境ではノイズが消えるだけでフォールバックは自動。

## この案の弱点・落選しうる理由（正直に）

1. **「めくる」が本当に速いのか、検証していない。** 帯をなぞる操作は、タブを直接押すより1動作多いわけではないが、**目的の面が2つ先にあるとき**（一面→索引）はなぞりを2回、または名前を押す1回になる。結局「名前を押す」が最速で、めくりは装飾に留まるかもしれない。その場合この案の核（縦スクロールを主動作から降ろす）が空洞化する。
2. **1面＝1画面と言いながら、実際は各面が縦にスクロールする。** 棚の面は1666px、一面は1781pxある。「めくる軸と読む軸の直交」は成立しているが、「1面＝1画面」という宣言は守れていない。在庫を隠さないことを優先した結果だが、コンセプトの純度としては妥協である。
3. **紙のトーンが muninn の中身と合っているとは限らない。** ゴルフのスイング所見も中東情勢も哲学史も、日刊紙の体裁で組むと**全部が「ニュース」の顔をする**。本人の身体知（insight）まで新聞活字で組まれることに違和感が出る可能性がある。
4. **明朝依存。** 上記のとおり、Androidや一部環境で明朝が落ちるとゴシック一色になり、この案の対比構造がまるごと失われる。単一書体でも成立する設計にはなっていない。
5. **「尖りすぎ」の持続不能性。** Bloomberg Businessweek が2017年に落ち着いたトーンへ戻った（`05` 1-2）のと同じ道を辿るリスク。毎日開くものとして、版ズレ・朱の柱・級数の落差が半年後にうるさく感じられないかは、実際に住んでみないとわからない。
6. **想起カードの反転（180ms）は、Superhuman基準からは遅い。** 「めくる」という比喩を守るために払ったコストだが、1日5回繰り返す操作としては合計1秒近い純粋な待ちになる。比喩を捨てて即時表示にするほうが正しい可能性がある。

## 追記: 題字の数字と `DESIGN.md` §8 の衝突をどう解決したか

初版の題字には「第 56 号」を出していた。これは `web/DESIGN.md` §8「意図的にやらないこと」が名指しで禁じている項目に抵触する:

> **号数・発行部数のような演出** — 新聞メタファーの装飾的な部分。中身がないのに様式だけ真似ない

指摘を受けて2段階で直した。

1. まず「創刊からの日数＋1」に変えたが、**これは解決になっていなかった**。この数は muninn に何も書かなくても毎日1ずつ増える——**蓄積を1つも増やしていない日でも号数だけが進む**ので、禁止の理由（中身がないのに様式だけ真似る）にそのまま当てはまるうえ、原則9「数字に嘘をつかせない」にも触れる。
2. 最終的に**号数という概念そのものを題字から外し**、正本から機械的に数えられる実体に置き換えた:

```js
// 記事 + 章 + 観測 + 記録 = これまでの書き足しの回数
writeCount() = MN.notes.length
             + Σ atlases[].concepts.length
             + Σ follows[].sessions.length
             + Σ logtopics[].entries.length     // 現在 112
```

題字には「書き足し **112** 回」と組む。**書いた分だけ増える量**なので、原則3（出してよいのは増えるカウンタだけ／減らない借金は禁止）にも適合する。The Marginalian が「15年分の物量を隠さず見せる」ことで説得力を作ったのと同じ手を、様式を捨てずに使えた。

`DESIGN.md` §8 の**改訂は提案しない**。禁止の理由（「中身がないのに様式だけ真似ない」）は正しく、今回の解はその禁止を破らずに紙面性を保てているため、原則の側を触る必要がない。

**あわせて修正した組版バグ**: 記事本文の末尾に markdown の見出し記号（`#`）が生で漏れていた。本文は正本の冒頭抄録なので末尾で記法が切れることがあり、`tidyMd()` で「抄録で切れた見出し記号・閉じていない強調・途中で切れた `[[`」を紙面に出す前に落とすようにした。
