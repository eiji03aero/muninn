赤字

  • 1

    リード枠は6状態すべてを実装してから出荷する。 落ちてくる順は speed → milestone → chapter-new → brief → feature → revival。この枠が空になる絵を1枚も作ってはいけない——記事が1件でもあれば revival（最終更新が最も古い群からの日替わり）が必ず出る。各状態は §03 に描いた。申し送り①現状のホームは「直近の更新7件」が枯れると死ぬ。ここが構造的に死なないことが、低頻度更新（数日〜週単位）という文脈への回答そのもの。

  • 2

    再読カードは3状態を必ず用意する（recallあり伏せ／めくり後／recallなしdegrade）。そして自己判定ボタンの下に、後から一言入力欄を差し込める可変高さの余白を最初から確保しておく。Phase1は「わかった／あやしい」の2択だけでよいが、レイアウトを破綻させずに追加できる構造にすること。申し送り②③審査で名指しされたC案の致命的弱点＝2択自己申告が mn-review の採点規律を骨抜きにする。一言を書かせて q を分岐させるのが処方箋（§15）。

  • 3

    特集の見出しタップは /shelf/:tag の該当束へアンカーで着地させる（棚板の先頭ではなく、その束の位置まで）。面 → 棚が「同じ束」で繋がることで、編集された面と網羅把握の面が地続きになる。

  • 4

    紙面はビルド日ではなく閲覧日（クライアントの new Date()）で組む。 build-data.mjs の due フラグ計算は廃止し、srs.next を素で渡すこと。PO移植④push が2週間止まっても、再読3枚・特集・復刻・連載は毎日入れ替わる。「更新頻度が低い」という制約への直接の解。

  • 5

    KPIタイル2×2と「復習期限 59」バッジは全撤去。 DueBadge コンポーネント自体を消す。数えるのは「今週12件 再読した」という成果だけ。knowledge 59件が全件期限切れで常時点灯＝情報量ゼロの壁紙。減らない借金の額は行動を止める。両審査員が独立に同じ指摘をした。

15全画面共通の規約

規約内容出典
つながりは全型必須 note / concept / entity / session / logentry の全詳細ページに「ここへ来る道」を同じ文言・同じ位置で置く。0件時の空状態も共通。型によって有無が分かれる実装を禁止する B案移植・両審査員一致
数えるのは成果だけ 未消化の件数をバッジで出さない。「復習期限 59」「KPIタイル2×2」「DueBadge」は全廃。出すのは「今週12件 再読した」 両審査員一致
紙面は閲覧日で組む ビルド時は素材の下ごしらえまで。「今日どれを載せるか」はクライアントの new Date()。due フラグのビルド時計算は廃止し srs.next を素で渡す PO移植④
影SRSは同一SM-2式 localStorage 側と /mn-review 側でまったく同じ式を使う。値が必ず一致するので乖離しない。同期判定は site.notes[slug].srs.last >= pending.date で「反映済み」とみなして pending から削除し、サーバ値で上書き PO移植③（自己修復同期）
自己判定の質を守る ①一言入力の有無で q を分岐（書いてわかった=q5 / 書かずわかった=q4 / あやしい=q2）②site由来の ease 成長を skill 由来より2〜3割抑える ③伝票20件で校正チェックポイント デザイン統括・最大リスクの処方箋
グラフの憲法 一度に描くノードは12点まで／レイアウトは決定的（乱数・force-directed 禁止）／図は必ずリストで代替可能にする B案移植
維持するもの ダークなグラス質感（theme.js 11トークン）／モバイルファースト・env(safe-area-inset-*)／PWA／パスワード1枚／完全静的／正本はmarkdown 刷新で触らない
