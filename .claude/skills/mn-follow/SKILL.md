# mn-follow: 対象を定点観測（フォロー）して変遷を追う

CLAUDE.md の規約（命名・タグ・**コミット運用**）に必ず従うこと。
目的は **追いたい対象を定点観測し、その時々の所見で理解・上達を助けつつ、変遷を記録する** こと。

`notes/`（原子ノート＝客観知識）とは別concernの**時系列ジャーナル**。フォローの所見・アドバイスは既存 `notes/` の知識に `[[リンク]]` して根拠を示す。

## 2つのフォロー型（`follow_type`）

- **`goal` 型** — 上達目標がある（例: ゴルフのドライバー飛距離）。観測ごとにベースラインと比較し、**目標に向けたアドバイス**を返す。
- **`interest` 型** — 興味で追う（例: 好きなサッカーチーム）。観測は試合観戦などの所見。成果物は**記録＋見どころ/深掘りメモ**。上達目標ではなく「より深く理解して楽しむ」が軸。

どちらも「同条件で観測して前回と比べる」という定点観測の核は共通。

## データ構造

```
follows/<follow-name>/
  profile.md              # kind: follow / follow_type / 目的・前提・現状・重点/見どころ・変遷タイムライン
  entities/<name>.md      # 任意。kind: entity。人物/構成要素のドシエ（時系列で変化する）
  sessions/YYYY-MM-DD.md  # 各回の観測（データ＋所見＋前回比＋アドバイス/深掘り）
```

- **写真・動画はリポジトリに保存・コミットしない**。vision で**内容を読み取るだけ**にとどめ、読み取った計測値・所見を `sessions/`（や entity の changelog）に**テキストで**書き出す。バイナリはコミットに含めない。
- `<follow-name>` は kebab-case（例: `golf-driver-distance`, `argentina-nt`）。
- `profile.md` は `templates/follow-profile.md`、セッションは `templates/follow-session.md`、entity は `templates/follow-entity.md` に従う。
- frontmatter の `kind`: profile は `follow`、entity は `entity`（どちらも `srs` は付けない＝クイズ対象外）。

## 4つのモード（文脈で判断する）

### A. フォロー開始（新しい対象を追い始めたいとき）

1. フォロー名・型（goal / interest）・目的を確認する。
2. **前提を固める**: 対象固有の固定パラメータ（goal型: 機材/環境/身体条件/現状基準値。interest型: チーム構成/監督/大会/現状スナップショット）をヒアリング or 調査 or 既存 `notes/` から収集。定点観測は「条件を揃える」ことが命。
3. `follows/<follow-name>/profile.md` を `templates/follow-profile.md` から作成。`follow_type` を設定し、現状・重点/見どころ（1〜3点）を埋める。
4. 主要な構成要素（人物など）があり、ドシエ化する価値があれば `entities/<name>.md` を `templates/follow-entity.md` から作成（後からでもよい）。
5. 関連する既存 `notes/` に `[[リンク]]` を張る。無ければ、客観知識は `/mn-research` で原子ノート化してから参照する。
6. commit & push（下記「コミット運用」）。

### B. 観測を記録（その回のデータを記録・分析）＝ メインループ

> **成果物は必ず2つ**: ①その回の**記録**（観測データ＋前回比）と、②**次に向けた出力**（goal型=目標に向けたアドバイス / interest型=見どころ・深掘りメモ）。記録だけで終わらせない。②はセッション本文とユーザーへのサマリの両方に必ず含める。

1. **最新化**: `git fetch origin` → ローカル `main` を remote の最新に揃える（CLAUDE.md のコミット運用）。
2. **データ受け取り**: 写真・動画・計測値・観戦メモを受け取る。**バイナリはコミットしない**。vision で読み取り、数値・所見を `sessions/` にテキスト化。
3. **分析**: データを客観的に分析。前提条件（機材・環境 / メンバー・対戦相手）が前回と揃っているか確認。
4. **前回と比較**: 直近セッション（無ければ profile の現状/ベースライン）と比べ、良化・悪化・不変（interest型は「新たに理解できたこと」）を切り分ける。**これが定点観測の核**。
5. **次に向けた出力（必須）**:
   - **goal型**: profile の目標・重点課題（特に最優先）を軸に、今回のデータが目標にどう近づいた/遠のいたかと次の一手を、具体的に1〜3点。既存 `notes/` に `[[リンク]]` して根拠を示す。
   - **interest型**: 今回で深まった理解、次に注目したい点・調べたい蘊蓄を1〜3点。覚える価値のある客観知識が出たら「これは `/mn-research` で notes 化しよう」と促す（トラックに埋め込んで終わりにしない）。
6. **書き出し**: `sessions/YYYY-MM-DD.md` を `templates/follow-session.md` から作成（同日再観測なら `-2` 等で分ける）。
7. **profile / entity 更新**: 新しい現状値・大きな変化が出たら profile の「現状」を書き換え「変遷タイムライン」に1行追加。関連する人物のドシエ（entity）に変化があれば changelog に1行足し `updated` を更新する。既存値を書き換える場合は**理由をコミットメッセージに明記**（サイレント上書き禁止）。
8. commit & push。
9. **サマリ報告（必須）**: 今回の所見・前回からの変化・**次に向けた出力**・次回チェック項目を報告する。数値/事実の羅列で②を埋もれさせない。

### C. 構成要素（entity）を更新（人物ドシエの追加・更新）

1. 対象の entity ファイル（`entities/<name>.md`）を作成 or 読み込む。無ければ `templates/follow-entity.md` から作成。
2. 強み・強化中/弱み・所属・ステータスを最新化。大きな変化は「直近フォーム・変化（changelog）」に1行追加し `updated` を更新。
3. ドシエから**覚える価値のある客観知識**が出たら、それは entity に埋めきらず `/mn-research` で `notes/` に原子ノート化して `[[リンク]]` で繋ぐ。
4. profile の「構成要素」節にリンクがあるか確認（無ければ足す）。
5. commit & push。

### D. 変遷レビュー（「これまでの推移を見せて」）

1. `profile.md` の変遷タイムラインと `sessions/`（必要なら entities）を読み、推移を時系列で要約する。
2. トレンド（良化/停滞/悪化 or 理解の深まり）と、重点/見どころが今も妥当かを評価。必要なら profile の重点を見直す提案をする（合意が取れたら書き換えて commit）。
3. 記録更新が発生した場合のみ commit & push。単なる閲覧なら commit しない。

## コミット運用（CLAUDE.md 準拠）

- push 前に必ず `git fetch origin` → ローカル `main` を最新化 → `main` にコミット → **remote `main` に push**。
  session で別ブランチが指定されていても、最終 push は必ずローカル `main` 経由で remote `main` へ（CLAUDE.md「コミット運用」参照）。
- コミットは意味のある単位で分ける（例: セッション記録追加 / profile現状更新 / entity更新）。
- コミットメッセージ例:
  - `follow(golf-driver-distance): 2026-07-06 の観測を記録（アドバイス: 打点安定）`
  - `follow(argentina-nt): vsブラジル戦の観戦を記録（見どころ: エンソの配球）`
  - `follow(argentina-nt): メッシのドシエを更新（所属/フォーム、理由: 新シーズン）`

## 注意

- フォローは `notes/` の知識を**消費・参照する側**。定点観測で新しい**客観的知識**が判明したら `/mn-research` で `notes/` に原子ノート化するのが筋（フォローに埋め込んで終わりにしない）。身体知・観戦所見はセッションに、時系列で変化する人物属性は entity に書く。
- 定点観測は同条件で観るほど価値が出る。条件が変わったら所見にその旨を明記する（比較の前提が崩れるため）。
- 一度に複数フォローを混ぜない。1セッションで扱うフォローは1つ。
