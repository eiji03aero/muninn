# mn-research: 記録（必要なら調査も）→原子化→記録

CLAUDE.md の規約（命名・原子化・リンク・タグ・コミット運用）に必ず従うこと。

## 発火条件（重要）

このskillは **明示的に記録を頼まれたときだけ** 使う。

- 使う例: 「これnotesにしておいて」「ナレッジに追加して」「記録して」「ノートにして」「これで保存して」「保存しておいて」
- 使わない例: 「〜について調べて」「調べてまとめて」「教えて」 → これらは記録の意思が明示されていないので、**普通にチャットで調査して答えるだけ**。`notes/` への書き込みやcommitはしない。後から「これnotesにして」「これで保存して」などと言われた時点で初めてこのskillを使う。

## 手順

1. **調査（必要な場合のみ）**: 記録対象がまだ会話内で調べられていなければ調査する（WebSearch / WebFetch 等、一次情報優先）。既に会話で調査済みなら再調査せず、その結果を原子化対象にする。
2. **原子化設計**: 書き始める前に、調査結果を1ノート1アイデアに分割する計画を立てる。
   - 作るノートの一覧（ファイル名・タイトル）
   - 各ノートのタグ（既存タグを Grep で走査してから決める）
   - ノート間および既存ノートとのリンク
   - 更新が必要なMOC
3. **重複チェック**: 既存の `notes/` を走査（Grep で title / tags）し、同じアイデアのノートがあれば新規作成せず統合する。
4. **ノート作成**: `templates/note.md` に従って `notes/` に作成。
   - 要約は自分（ユーザー）の言葉で書く。原文の丸写しをしない。
   - 出典がある場合は本文末尾に `## Sources` セクションを設けてURLを残す。
5. **逆リンク**: 関連する既存ノート側にも逆方向の `[[リンク]]` を追記する。
6. **MOC更新**: 該当するMOCを更新（なければ作成を検討）。`moc/home.md` から全MOCに到達できることを確認。
7. **コミット＆プッシュ**: push する前にまず `git fetch origin` でローカルの `main` を remote の最新に更新（`git pull --rebase origin main` 等）し、その最新の `main` に意味のある単位でコミット（別ブランチで作業した場合は `main` にマージ）してから、**必ず remote に push する**（記録依頼にはpushまで含まれる）。既存ノートを変更・統合した場合は理由をコミットメッセージに明記。
8. **サマリ報告**: 「作成したノート一覧 / 統合・変更した既存ノート / 新設したタグ・MOC / 判断に迷った点」を報告する。人間はこれと `git show` で事後レビューする。

## 注意

- 調査結果を `inbox.md` に書き出さない。このskillは「文脈が一番濃いその場で原子化する」ための直接ルート。
- 調査が長大な場合も原子化を妥協しない。10ノートになるなら10ノート作る。
