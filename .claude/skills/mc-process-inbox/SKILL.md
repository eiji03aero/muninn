# mc-process-inbox: inboxバッチ処理

CLAUDE.md の規約（命名・原子化・リンク・タグ・コミット運用）に必ず従うこと。

## 手順

1. **精査**: `inbox.md` を読み、項目を洗い出す。1項目に複数の独立した知識が含まれる場合は分割する。
2. **原子化設計**: 書き始める前に全体の計画を立てる。
   - 作るノートの一覧（ファイル名・タイトル）
   - 各ノートのタグ（既存タグを Grep で走査してから決める）
   - ノート間および既存ノートとのリンク
   - 更新が必要なMOC
   - 意味が取れない・曖昧すぎる項目は無理に原子化せず、サマリで人間に確認する
3. **重複チェック**: 既存の `notes/` を走査し、同じアイデアのノートがあれば新規作成せず統合する。
4. **ノート作成**: `templates/note.md` に従って `notes/` に作成。要約は自分（ユーザー）の言葉で書き直すが、雑メモのニュアンスを勝手に拡大解釈しない。
5. **逆リンク**: 関連する既存ノート側にも逆方向の `[[リンク]]` を追記する。
6. **MOC更新**: 該当するMOCを更新（なければ作成を検討）。`moc/home.md` から全MOCに到達できることを確認。
7. **inbox掃除**: 処理済み項目を `inbox.md` から削除する。処理できなかった項目は残し、行頭に `<!-- 要確認: 理由 -->` を付ける。
8. **コミット**: mainに意味のある単位でコミットしてpushする（例: ノート作成 / MOC更新 / inbox削除）。
9. **サマリ報告**: 「作成したノート一覧 / 統合・変更した既存ノート / 新設したタグ・MOC / 処理できなかった項目と理由 / 判断に迷った点」を報告する。
