# mn-capture: 種別を意識させない単一入口（仕分け＆ルーティング）

CLAUDE.md の規約（命名・原子化・リンク・タグ・コミット運用）に必ず従うこと。
このskillは muninn の**フロントドア**。ユーザーが「今どの機能を使ってるか」を意識しなくて済むよう、投げられた内容を判定し、**該当ルートの手順どおりに処理**して相互リンクする。

## 発火条件

- `/mn <内容>` で呼ばれたとき。
- 種別を明示せず**記録の意思**を持って投げられたとき（「これ記録して」「入れといて」「メモっといて」「保存して」）。
- **単なる「調べて」「教えて」（記録の意思なし）では発火しない** — その場合はチャットで答えるだけ（mn-research と同じ原則）。
- ユーザーが特定ルートを名指し（`/mn-research` 等）した場合は、そのskillを直接使う。

## 仕分けルーブリック（各項目をこの順で判定）

| 内容 | ルート | 実行手順 |
|------|--------|----------|
| 外部の**客観的事実**（調べた/貼った/教わった知識） | **knowledge ノート** | `mn-research` の原子化手順。`srs` 初期化＝クイズ対象 |
| 自分の**解釈・身体知・メタ原則・気づき** | **insight ノート** | `notes/` に作成。`srs` は付けない |
| すでに追ってる**フォローの観測**（試合を観た/練習した/計測した） | **session** | `mn-follow` モードB。`follows/<name>/sessions/` |
| **新しく追いたい対象** | **follow profile 新設** | `mn-follow` モードA |
| **人物/構成要素**の属性・ドシエ更新 | **entity 作成/更新** | `mn-follow` モードC。`follows/<name>/entities/` |
| 曖昧すぎる/その場で原子化できない | **inbox 退避** | `inbox.md` に追記（後日 `mn-process-inbox`）。または一言確認 |

## 手順

1. **最新化**: `git fetch origin` → ローカル `main` を remote の最新に揃える（CLAUDE.md のコミット運用）。
2. **分解**: 投げられた内容を独立項目に分解する。**1つの投稿に複数種別が混在するのが普通**（例: 試合観戦メモ → ①session ＋ ②そこで学んだ戦術＝knowledge ノート ＋ ③選手の変化＝entity 更新）。混在は分割して各々を処理する。
3. **分類**: 各項目を上のルーブリックで分類。判定が明確なものは即実行してよい。**曖昧な項目だけ**ユーザーに一言確認する（対話の往復を増やしすぎない）。
4. **処理**: 各項目を該当ルートの**正式手順どおり**に処理する（原子化・タグは既存を Grep してから・命名規約を厳守）。該当skillの手順を参照すること（knowledge=mn-research / session・follow・entity=mn-follow）。
5. **相互リンク（最重要）**: このskillの価値は**横断リンク**にある。処理した項目どうし、および既存ノートと必ず双方向に繋ぐ。
   - session ↔ 登場した entity ↔ そこで得た knowledge ↔ フォローの profile
   - entity ↔ そのプレースタイル等を説明する knowledge ノート
   - 「なぜ関連するか」を一言添える（確信のない連想リンクは張らない＝CLAUDE.md）。
6. **MOC更新**: 新テーマの knowledge を作ったら該当MOCを更新（無ければ作成を検討）。`moc/home.md` から到達できることを確認。
7. **コミット＆プッシュ**: 意味のある単位で分けてコミットし（例: notes作成 / session記録 / entity更新）、CLAUDE.md のコミット運用に従って **remote `main` に push**。
8. **サマリ報告（必須）**: 「各項目を**どのルートに・どのファイルとして**入れたか」「張った横断リンク」「新設タグ/MOC」「迷って確認した点」を報告する。**仕分けは訂正可能**であることを明示し、ユーザーが「それは insight じゃなく knowledge」等と直せるようにする。

## 注意

- 仕分けの主目的は「ユーザーにモードを選ばせない」こと。だが**間違った仕分けは資産を汚す**ので、確信が持てない項目は勝手に確定せず確認する。
- knowledge と insight の仕分けは「外部の事実を調べて得たか（knowledge）／自分の経験・解釈から来るか（insight）」で判断（CLAUDE.md「種別（kind）」）。
- フォロー観測で得た**覚える価値のある客観知識**は、フォローに埋め込まず必ず knowledge ノートに切り出してクイズ母集団に乗せる（統合の肝）。
