# mn-track: スキル上達の定点観測

CLAUDE.md の規約（命名・タグ・**コミット運用**）に必ず従うこと。
目的は **上達したいスキルを定点観測し、その時々のアドバイスで上達を助けつつ、変遷を記録する** こと。

`notes/`（原子ノート＝知識）とは別concernの**時系列ジャーナル**。トラックのアドバイスは既存 `notes/` の知識にリンクして根拠を示す。

## データ構造

```
tracks/<track-name>/
  profile.md            # 目的・機材/前提・現在の基準値・目標・変遷タイムライン
  sessions/YYYY-MM-DD.md # 各回の観測（アップしたデータ＋所見＋前回からの変化＋アドバイス）
```

- **写真・動画はリポジトリに保存・コミットしない**。アップされた画像/動画は vision で**内容を読み取るだけ**にとどめ、読み取った計測値・所見を `sessions/` に**テキストで**書き出す。バイナリはコミットに含めない。

- `<track-name>` は kebab-case で内容を表す。例: `golf-driver-distance`, `english-speaking`。
- `profile.md` は `templates/track-profile.md`、セッションは `templates/track-session.md` に従う。
- `profile.md` の frontmatter は `kind: track`（`srs` は付けない＝クイズ対象外）。

## 3つのモード（文脈で判断する）

### A. トラック開始（新規スキルの定点観測を始めたいとき）

1. トラック名・目的・ゴールを確認する。
2. **基本情報を取る**: そのスキルに固有の固定パラメータ（機材スペック、環境、身体条件、現状の基準値）をヒアリング or 既存 `notes/` から収集する。定点観測は「条件を揃える」ことが命なので、何を固定するかをここで決める。
3. `tracks/<track-name>/profile.md` を `templates/track-profile.md` から作成。基準値・目標・重点課題（1〜3点に絞る）を埋める。
4. 関連する既存 `notes/` に `[[リンク]]` を張る。
5. commit & push（下記「コミット運用」）。

### B. 観測を記録（その日のデータをアップして記録・アドバイス）＝ メインループ

> **このモードの成果物は必ず2つ**: ①その日の**記録**（観測データ＋前回比）と、②**目標達成に向けたアドバイス**。記録だけで終わらせない。アドバイスは profile の**目標・重点課題（特に最優先の課題）に紐づけて**返し、セッション本文とユーザーへのサマリの両方に必ず含める。

1. **最新化**: `git fetch origin` → ローカル `main` を remote の最新に揃える（CLAUDE.md のコミット運用）。
2. **データ受け取り**: 写真・動画・計測値を受け取る。
   - **写真・動画はコミットしない**。vision で内容を読み取り、読み取った計測値・所見を `sessions/` にテキストで書き出すだけにとどめる（画像バイナリはリポジトリに保存しない）。
   - 計測値（数値）は所見にそのまま書き出す。
3. **分析**: アップされたデータを vision 等で客観的に分析する。前提条件（機材・環境）が前回と揃っているかも確認する。
4. **前回と比較**: 直近セッション（無ければ profile のベースライン）と比べ、良化・悪化・不変を切り分ける。**これが定点観測の核**。
5. **アドバイス（必須）**: 次に向けて具体的に1〜3点。**profile の目標・重点課題（特に最優先の課題）を軸に**、今日のデータが目標にどう近づいた/遠のいたかと、次に何をするかを結びつける。既存 `notes/` の知識に `[[リンク]]` して根拠を示す。今日のデータが最優先課題と別の指標を示している場合は、なぜその軸で助言するか一言添える。**アドバイスは省略しない**（記録だけで終わらせない）。
6. **書き出し**: `sessions/YYYY-MM-DD.md` を `templates/track-session.md` から作成（同日再観測なら `-2` 等で分けるか追記）。
7. **profile 更新**: 新しい計測値が出たら「現在の基準値」を書き換え、「変遷タイムライン」に1行追加する。基準値を書き換える場合は**なぜ変えるかをコミットメッセージに明記**（既存内容のサイレント上書き禁止）。
8. commit & push。
9. **サマリ報告（必須）**: 今日の所見・前回からの変化・**目標に向けたアドバイス**・次回チェック項目を報告する。数値変化だけを並べてアドバイスを埋もれさせない。アドバイスは目標/重点課題への進捗と紐づけて明示的に述べる。

### C. 変遷レビュー（「これまでの推移を見せて」）

1. `profile.md` の変遷タイムラインと `sessions/` を読み、推移を時系列で要約する。
2. トレンド（良化/停滞/悪化）と、重点課題が今も妥当かを評価する。必要なら profile の重点課題を見直す提案をする（合意が取れたら書き換えて commit）。
3. 記録更新が発生した場合のみ commit & push。単なる閲覧なら commit しない。

## コミット運用（CLAUDE.md 準拠）

- push 前に必ず `git fetch origin` → ローカル `main` を最新化 → `main` にコミット → **remote `main` に push**。
  session で別ブランチが指定されていても、最終 push は必ずローカル `main` 経由で remote `main` へ（CLAUDE.md「コミット運用」参照）。
- コミットは意味のある単位で分ける（例: セッション記録追加 / profile基準値更新）。
- コミットメッセージ例:
  - `track(golf-driver-distance): 2026-07-06 の観測を記録（アドバイス: 打点安定）`
  - `track(golf-driver-distance): 基準値を更新（ミート1.39→1.42、理由: 新計測）`

## 注意

- トラックは `notes/` の知識を**消費・参照する側**。定点観測で新しい**客観的知識**が判明したら、それは `/mn-research` で `notes/` に原子ノート化するのが筋（トラックに埋め込んで終わりにしない）。身体知・所見はセッションに書けばよい。
- 定点観測は同条件で撮るほど価値が出る。条件が変わったら所見にその旨を明記する（比較の前提が崩れるため）。
- 一度に複数トラックを混ぜない。1セッションで扱うトラックは1つ。
