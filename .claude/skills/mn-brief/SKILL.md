# mn-brief: 蓄積を横断合成して「予習ブリーフィング」を作る

CLAUDE.md の規約に従うこと（ただし既定では**書き込みをしない**＝閲覧・想起のためのskill）。
目的は、バラバラに貯めた knowledge / entity / follow / session を**1つのブリーフィングに束ねて想起を助け、対象をより深く楽しめる状態にする**こと。muninn の「思い出す」面であり、蓄積を"楽しむ"に変換する回収装置。

## いつ使うか

- 「アルゼンチンvsブラジルの前に予習させて」「今のアルゼンチンの見どころは？」
- ある人物・テーマについて「今わかってることを束ねて」
- レビュー本番（`mn-review`）とは別。ここでのクイズは**想起補助**で、`srs` も `review-log.jsonl` も**更新しない**。

## 手順

1. **対象と目的を確認**: フォロー名/テーマ/人物と、目的（例: 試合前予習、人物理解）を特定する。曖昧なら一言確認。
2. **収集（横断）**: 対象に関係する素材を集める。
   - フォローなら `follows/<name>/profile.md`（現状・見どころ・タイムライン）＋ `entities/*.md` ＋ 直近 `sessions/`。
   - 関連する `notes/`（`kind: knowledge` / `insight`）を、タグと `[[リンク]]` を辿って収集（Grep）。
   - テーマ指定なら該当MOCを起点に notes を集める。
3. **合成（ブリーフィング本体）**: 以下を簡潔に構成する。冗長な貼り付けをせず、要点に圧縮する。
   - **現状スナップショット**: profile の現状・ストーリーライン（interest型）や基準値（goal型）。
   - **注目の構成要素**: 主要 entity の役割・強み・強化中の点・見どころ・参考クリップ。
   - **押さえる客観知識**: 関連 knowledge ノートの要点・蘊蓄（該当ノートに `[[リンク]]`）。
   - **見どころ / 注目ポイント**: 「今回これを見ると面白い」を2〜4点。
4. **想起チェック（任意）**: 関連 knowledge から2〜3問のミニクイズを出し、ユーザーの想起を助ける。**`srs`/ログは更新しない**。理解が浅い点が見つかったら「`mn-review` で定着させよう」と促す。
5. **穴の指摘**: ブリーフィング中に「まだ notes 化されていない重要知識」に気づいたら、「`/mn` で記録しよう」と促す（想起が次の蓄積を駆動する）。
6. **出力**: 原則チャットのみ（**commitしない**）。ユーザーが「残して」と言った場合のみ、`follows/<name>/sessions/` かテーマ別の場所に保存し、CLAUDE.md のコミット運用で push する。

## 注意

- ブリーフィングは**蓄積の再利用**。ここで新しく調べた客観知識は、埋め込んで終わりにせず `/mn`（→ mn-research）で notes 化する。
- 想起クイズと本番クイズ（mn-review）を混同しない。こちらはスケジューリングに影響を与えない。
