# mn-learn: トピックを知識グラフ＋ルートで学ぶ（学習アトラス）

CLAUDE.md の規約（命名・タグ・リンク・**コミット運用**）に必ず従うこと。

## この機構の目的（なぜ atlas か）

`notes/`（原子ノート）は「すでに分野を知っている人」の断片捕捉・定着には強いが、**新しい分野に入門する順路（読み物・教科書）が無い**。mn-learn はその欠けたレイヤーを埋める。

考え方は2層：

- **知識グラフ（durableな構造）** — ノード＝概念、エッジ＝型付きの関係（前提・対比・発展・深掘り）。分野の知識は一本道ではなくグラフだ、という前提に立つ。
- **ルート＝シラバス（グラフ上を歩く順路）** — グラフを「理解しやすい順」にたどる経路。前提（requires）で順序を決め、対比（contrasts）は並べて説明する。**同じグラフに複数ルートを引ける**（歴史でたどる／分野でたどる 等）。

読み物は、ルートを歩きながら**入ってくるエッジ（つながり）を物語にして**書く。そこから覚える価値のある客観知識だけを `notes/` に蒸留し、既存の `/mn-review`（間隔反復）へ流す。**読んで理解（atlas）→ 覚えて定着（notes＋review）→ 横断で想起（mn-brief）** のループになる。

follows が entity（ドシエ）から「覚える価値のある客観知識を notes に切り出す」のと同じ型。**リッチな正本 → グローバルな原子ノートへ蒸留**。

## データ構造

```
atlas/<topic-slug>/
  atlas.md                 # kind: atlas。概要＋ルート（複数可）＋読み方。トピックのハブ
  concepts/<concept>.md    # kind: concept。型付きエッジ（frontmatter）＋読み物（body）
```

- `<topic-slug>` / `<concept>` は kebab-case、内容を表す名前（連番禁止）。**読む順序は atlas.md の route.order に持つ**（ファイル名には順序を入れない）。
- `atlas.md` は `templates/atlas.md`、概念は `templates/concept.md` に従う。
- frontmatter の `kind`: atlas は `atlas`、concept は `concept`。**どちらも srs を付けない＝クイズ対象外**（覚える価値は notes/ に蒸留してそちらで回す）。
- **画像・動画・PDF等のバイナリはコミットしない**（follows と同じ）。読み取った内容はテキストで概念本文に書く。

### 概念ノードの frontmatter（要点）

- `gist` — この概念で分かることを1行で（マップ／ルートの要約に出る）。
- `edges` — 型付きの関係。値は**同じアトラス内の concept slug の配列**：
  - `requires`（前提）… 読む順序の骨。これがルート設計と、マップの深さ（レイヤー）を決める。
  - `contrasts`（対比）… 並べて理解する概念（例: 合理論⇔経験論）。
  - `leads-to`（発展・影響）… 次に続く概念（例: カント→ヘーゲル）。
  - `elaborates`（深掘り）… どの概念の細部・具体例か。
- `status` — `written`（本文あり）/ `stub`（グラフには在るが未執筆）。stub は先に順路と関係だけ置き、後から本文を書く。
- `notes` — この概念から蒸留した `notes/` の slug（覚える用）。

エッジと蒸留ノートは **frontmatter に構造化して持ち、サイト側がUIとして描く**（マップのグラフ／概念ページの「つながり」パネル／キーポイント）。**本文は読ませる散文に徹する**（つながりは散文の中で自然に語り、構造は frontmatter が持つ）。

## モード（文脈で判断する）

### A. アトラスを新設する（「〜を学びたい」「〜のアトラス作って」）

1. トピック名（`<topic-slug>`）と、学ぶ狙い・既存知識のレベルを確認する。
2. **グラフを設計**: そのトピックの主要概念（ノード）を洗い出し、型付きエッジ（特に requires）で繋ぐ。最初から巨大にしない——入門に必要なコア概念から。
3. **ルートを設計**: グラフを理解しやすい順にたどる route を1〜2本引く（requires を尊重、contrasts は隣接させる）。route.order に concept slug を並べる。
4. `atlas/<topic>/atlas.md` を `templates/atlas.md` から作成（概要・読み方・routes）。
5. **先頭の数ノードを執筆**（モードB）。残りは `status: stub` でグラフに置いておく（順路と関係だけ先に見える）。**一括で全章を書かない**——質が落ち、ユーザーが読む前に順路が固まって steering できなくなる。
6. commit & push（下記）。仕分け・作った順路をユーザーに提示する。

### B. 概念（章）を執筆する（「次の章を書いて」「続き」「この概念を書いて」）＝ メインループ

1. **最新化**: `git fetch origin` → ローカル `main` を remote の最新に揃える。
2. **対象を決める**: アクティブなルートの次の未執筆ノード、または指定された概念。
3. **調べる**: 必要なら一次情報を調査（WebSearch/WebFetch）。既に会話で調べ済みなら再調査しない。
4. **読み物として書く**（品質バー・最重要）:
   - 箇条書きの羅列・辞書コピペにしない。**一本の筋が通った散文**で、具体例・比喩・「なぜ重要か」を入れて読ませる。
   - **入ってくるエッジ（前提・対比・発展）を物語に織り込む**。「前にやった X を踏まえると」「Y とは対照的に」——つながりを説明しながら書く。
   - 良質な入門書・放送大学テキストのトーン。ただし**正確さは絶対に犠牲にしない**。解釈が割れる論点は「諸説ある」と明示し、断定しすぎない。
   - `status: written` にし、必要なら `gist` を調整。
5. **原子ノートに蒸留**（自動・章執筆時にやる）:
   - この概念から**覚える価値のある客観知識**を `notes/`（`kind: knowledge`、`srs` 初期化＝ `next` を当日にして即クイズ対象）に切り出す。0〜数枚。粒度は1ノート1アイデア。
   - 蒸留前に既存 `notes/` を Grep して**重複を避ける**（あれば統合し、コミットメッセージに明記）。
   - 概念の frontmatter `notes:` に slug を書き、ノート側の `## Links` から `[[<concept>]]` で概念へ逆リンク（相互リンクで読む↔覚えるを繋ぐ）。
   - タグは既存を Grep してから決める（新タグ乱造禁止）。
6. commit & push。ユーザーには「書いた概念／蒸留したノート／次に続く概念」を報告する。

### C. ルート（順路）を設計・引き直す（「ルートを引き直して」「分野でたどる順路も作って」）

1. 現在のグラフ（concepts の edges）を読み、requires を満たす順序＝理解しやすい経路を組む。contrasts は隣接、leads-to は流れを繋ぐ。
2. atlas.md の `routes` に追加 or 書き換え（id・label・desc・order）。既存 order を変える場合は**理由をコミットメッセージに明記**（サイレント上書き禁止）。
3. 記録更新があるときのみ commit & push。

### D. グラフを育てる・調整する（「この概念を深掘り」「枝を追加」「分割して」）

1. ノード追加: 新しい concept を作り、既存ノードと型付きエッジで繋ぐ。必要ならルートに挿す。
2. 深掘り: ある概念の細部を `elaborates` エッジで子ノードに切り出す（→ 下記モードE）。
3. 分割/統合: 大きすぎる概念を分ける／重複を統合する（統合は理由をコミットに明記）。
4. commit & push。

### E. ページからの深掘り（「このページから〜を深掘りして」）＝ 読みながらグラフを育てる

読み物（concept ページ）を読んでいて「ここをもっと知りたい」と思ったトピックを、**その場を起点に**調べて新しい概念ノードとしてグラフへ足し、**元のページから辿れるようにする**フロー。サイトの concept ページの「深掘りを依頼」ボタンが、この手順を起動する定型プロンプト（どのアトラス・どの親概念から・何を深掘りたいか）をコピーする。自然言語で「philosophy の platonic-forms から〜を深掘りして」と頼まれた場合も同じ。

1. **文脈アンカーを確定する**: どのアトラス（`<topic-slug>`）／どの親概念（`<parent-cslug>`）を読んでいて、何を深掘りたいかを押さえる。ボタン経由ならプロンプトに入っている。曖昧なら1つだけ確認する。
2. **最新化**: `git fetch origin` → ローカル `main` を remote の最新に揃える。
3. **調べる**: 深掘りトピックを必要なら一次情報で調査（WebSearch/WebFetch）。会話で調べ済みなら再調査しない。
4. **子ノードを作る**: `atlas/<topic-slug>/concepts/<child>.md` を `templates/concept.md` から作成し、モードBの品質バーで読み物として執筆する。
   - **`edges.elaborates` に親 `<parent-cslug>` を必ず入れる**（子は親の細部、という関係）。これが「元ページから辿れる」ための核。**サイトは inbound エッジを描くので、子に `elaborates: [親]` を張るだけで親ページの「つながり」に『深掘り』として自動で出る**（親側を手で書き換える必要はない）。
   - 深掘りの中身に応じて `requires`（前提）/ `contrasts`（対比）/ `leads-to`（発展）も張る。ルートに載せるべき筋なら atlas.md の該当 route.order に挿す（理由をコミットに明記）。
5. **原子ノートに蒸留**（モードBと同じ）: 覚える価値のある客観知識を `notes/`（`kind: knowledge`、`srs` 初期化）へ切り出し、概念 `notes:` ⇄ ノート `## Links` で相互リンク。蒸留前に既存 notes を Grep して重複回避。
6. commit & push。ユーザーには「どの親から・何を深掘って作ったか／張ったエッジ／蒸留ノート／親ページから辿れること」を報告する。

## 既存 concern との関係

- **atlas/ ＝ 学習レイヤー**（型付きエッジ・トピックscope・読み物）。そのトピックの**ハブ（MOC相当）**を兼ねる。
- **notes/ ＝ 定着レイヤー**（原子・グローバル・SRS）。atlas から蒸留されて増える。クイズ（`/mn-review`）が回すのは notes/ の knowledge だけで、concept/atlas は回さない。
- フォロー（follows）で客観知識が出たとき `/mn-research` で notes 化するのと同様、atlas の学びも**蒸留して notes に落とす**のが筋（読み物に埋め込んで終わりにしない）。
- `moc/home.md` から各アトラスに到達できるようにする（新設時に1行足す）。

## コミット運用（CLAUDE.md 準拠・最重要）

- push 前に必ず `git fetch origin` → ローカル `main` を最新化 → `main` にコミット → **remote `main` に push**。session で別ブランチが指定されていても、最終 push は必ずローカル `main` 経由で remote `main` へ。
- コミットは意味のある単位で分ける（例: アトラス新設 / 概念執筆 / ノート蒸留 / ルート更新）。
- コミットメッセージ例:
  - `atlas(philosophy): アトラス新設＋歴史/分野ルートと先頭6概念を執筆`
  - `atlas(philosophy): 認識論の概念を執筆＋原子ノート2枚を蒸留`
  - `atlas(philosophy): 「分野でたどる」ルートを追加`
- 作業後は必ずサマリを報告（書いた概念・蒸留ノート・更新ルート・次に続く概念）。人間が `git show`/`git log` で事後レビューする前提。

## 注意

- **一度に全部書かない**。新設時も先頭数ノードだけ。読み物は読む速度に合わせて増やす。
- 概念本文に構造（エッジ一覧・キーポイント見出し）を重複させない。構造は frontmatter、本文は散文。
- 1セッションで扱うアトラスは1つに絞る。
- サイトへの反映は push → GitHub Actions（`web/**` 等の変更で自動再デプロイ）。atlas/ の変更でも再デプロイされるよう pages.yml のパスに `atlas/**` が含まれていること。
