# mn-review: 客観知識を間隔反復クイズで定着させる

CLAUDE.md の規約（特に「種別（kind）とクイズによる定着」「コミット運用」）に必ず従うこと。
目的は **調べて得た客観的な知識を頭に定着させる** こと。**1セッション=1問**が基本。

## 出題対象

- `kind: knowledge` のノートのみ。`kind: insight` や `kind` 未設定のノートは**絶対に出題しない**。
- そのうち `srs.next` が**今日以前**（`next <= 今日`）のノートが母集団。
- 母集団が空（今日が復習日のノートがない）の場合は、その旨を報告して終了する。無理に前倒し出題しない。ただしユーザーが「前倒しでいいから出して」と言えば `next` が最も近いものから出してよい。

## 手順

1. **最新化**: `git fetch origin` → 作業ブランチを remote の最新に揃える（CLAUDE.md のコミット運用に従う。通常は `main`）。ローカルの `srs` が古いと二重採点になるため必ず先に行う。
2. **対象収集**: `notes/*.md` の frontmatter を走査（Grep等）し、`kind: knowledge` かつ `srs.next <= 今日` のノートを集める。
3. **1問選ぶ**: 母集団から1ノートを選ぶ。`next` が最も古い（最も復習が遅れている）ものを優先。同点ならその中からランダム。
4. **出題**: 選んだノートの**本文は見せず**、内容を問う問題を1問作る。
   - 単なる用語当てより、**理由・関係・適用**を問う形を優先（例:「鉄・ビタミンD・亜鉛のうち脱毛との関連エビデンスが比較的強いのはどれで、なぜそう言えるか」）。
   - 1ノート1アイデアなので、問いもそのノートの中心アイデア1点に絞る。
   - どのノートを出題したかは採点まで明かさない。
5. **採点**: ユーザーの自由記述の回答を、**ノート本文を正解として**突き合わせて評価する。
   - 品質 `q`（0–5）を付ける: 5=完璧 / 4=ほぼ正確に説明できた / 3=要点は合っているが不正確・不完全 / 2=部分的にしか合っていない / 1=ほぼ外した / 0=全く分からない・無回答。
   - 採点結果、正しい点・抜け・誤解、そしてノートの該当箇所を簡潔にフィードバックする。
   - **ノート本文の誤り・古さが判明した場合**は、その場で本文を修正する（理由はコミットメッセージに明記）。
6. **SRS更新（SM-2簡易版）**: 選んだノートの `srs` を以下で更新する。`今日` は `YYYY-MM-DD`。
   - `q < 3`（不正解扱い）: `interval = 1`、`ease` は据え置き（下限 1.3 を割らない）。
   - `q >= 3`（正解扱い）:
     - `interval == 0` なら `interval = 1`
     - `interval == 1` なら `interval = 6`
     - それ以外は `interval = round(interval * ease)`
     - `ease = ease + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))`、ただし最低 1.3。
   - `last = 今日`、`next = 今日 + interval 日`。
   - frontmatter の `srs` を書き換える（他のフィールド・本文は変更しない）。
7. **履歴追記**: `review-log.jsonl` に1行（1 JSON オブジェクト）を append する。スキーマ:
   ```json
   {"date":"2026-06-20","note":"protein-deficiency-causes-hair-shedding","q":4,"interval":6,"ease":2.5,"next":"2026-06-26","question":"出題した問い","answer":"ユーザーの回答（要約可）"}
   ```
   ファイルが無ければ新規作成。既存行は絶対に書き換えない（append-only）。
8. **コミット＆プッシュ**: `srs` 更新・`review-log.jsonl` 追記（本文修正があればそれも）を**1コミット**にまとめ、CLAUDE.md のコミット運用に従って push する。コミットメッセージ例: `review: <ノート名> をクイズ（q=4, next=2026-06-26）`。
9. **サマリ報告**: 出題ノート・あなたの理解度・次回復習日・（あれば）本文修正点を報告する。

## 注意

- **1問で終える**。ユーザーが「もう1問」と言った場合のみ続け、その場合も1問ごとに 4〜9 を繰り返す（コミットは問ごと or セッション末にまとめる、どちらでもよいが履歴は必ず全問分残す）。
- 採点は甘くしない。本人の言葉で要点を再構成できて初めて `q >= 4`。本文のキーワードに触れていない曖昧な回答は `q <= 3`。
- `insight` ノートを定着対象にしたくなった場合は、勝手に出題せず、ユーザーに `kind` 変更の意思を確認する。
