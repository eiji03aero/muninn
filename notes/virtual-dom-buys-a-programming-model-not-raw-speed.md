React のコンポーネントは実DOMではなく **React 要素のツリー（設計図の値）** を返す。状態が変わると関数が呼び直され、新旧の設計図を突き合わせて（**照合＝reconciliation**）差分だけを実DOMに当てる。この中間表現が **仮想DOM**。

**熟練者が手で書いた最小限のDOM操作より速くなることはない**——余分な木を毎回作っているのだから当然。仮想DOMが買っているのは**プログラミングモデル**のほうで、「毎回全部作り直す」という乱暴で分かりやすい書き味を、実用に耐える速度で成立させる装置である。

そもそも作り直さない方式（Solid / Svelte 等の細粒度リアクティビティ、シグナル）と比べると、仮想DOMが「必然」ではなく一つの選択だったことが分かる。
