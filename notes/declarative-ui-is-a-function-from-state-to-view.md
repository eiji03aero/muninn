命令的なDOM操作（jQuery的な書き方）では、状態が **JS側の変数** と **DOMの見た目** の二箇所に存在する「二重帳簿」になる。同期はイベントハンドラの網に依存し、イベント種類 n × 影響要素 m の組み合わせに穴が空くとバグになる。しかも画面が「どの経路で来たか」を記憶するため、再現しにくい。

宣言的UIはこれを反転させ、**差分の当て方を書かず「その状態のときの画面はこうだ」という完成形だけを書く**（`view = f(state)`）。差分適用はランタイムの仕事。`f` は純粋関数なので同じ状態なら必ず同じ画面になり、経路の記憶が消える。

**利得の本体は速度ではなく、開発者が守るべき不変条件が「状態と表示の同期」から「`f` の正しさ」に縮むこと。** 仮想DOM等の差分機構は、この書き味を現実的な速度で成立させるための代償であって目的ではない。
